# PC13 — 配置备份：一个文件、一个口令

日期：2026-11-22
范围：`platform/BundleCrypto.ets`、`service/ConfigBundle.ets`、`pages/Backup.ets`
设备：HarmonyOS 模拟器（x86_64），API 26

## 1. 要解决什么

配置导出的目的只有一个：**离开这台设备**——换机、重装（`KvStore` 会被清空），或把一份能直接用的配置交给别人。

它和订阅不是一回事：

| | 订阅 | 备份文件 |
| --- | --- | --- |
| 谁维护 | 上游，可自动更新 | 自己，某一刻的静态快照 |
| 存什么 | URL 别名（真 URL 在 Asset Store） | 节点全部字段 + 凭据密文 + 规则 |
| 断网/上游挂了 | 拉不到新的 | 文件在手就还能恢复 |

## 2. 为什么不用"含凭据开关"

一个开关让用户在"有用"和"安全"之间二选一，实际结果是大家都会勾上它——于是凭据明文进了会被微信传走的文件。

改成**始终加密**：文件可以随便传，**口令另走一条渠道**。这样"备份"和"分享"变成同一个产物，不需要用户先想清楚用途。

## 3. 文件格式

```json
{
  "format": "tunnelix-bundle",
  "version": 1,
  "kdf": "PBKDF2|SHA256",
  "iterations": 200000,
  "salt": "<base64, 16B, 每次导出随机>",
  "cipher": "AES256|GCM|NoPadding",
  "nonce": "<base64, 12B>",
  "body": "<base64, 密文+16B tag>",
  "meta": { "exportedAt": 0, "nodeCount": 0, "ruleCount": 0, "hasCredentials": true }
}
```

- **明文部分只有 meta**：导出时间、条目数、是否含凭据。**不含节点地址、不含设备标识**——文件可以被看到"这是什么"，但看不到"连到哪"。
- `salt` 每次随机：同一口令导两次，密文不同。
- `iterations` 随文件走：将来提高强度不会被旧文件卡住。

## 4. 加解密

`PBKDF2-SHA256(口令, salt, 200000)` → 32 字节密钥 → `AES-256-GCM(12B nonce, 16B tag)`。

GCM 自带完整性校验：**口令错、文件被改、版本不符，都是同一个"打不开"**，不做"尽量恢复"——硬解出来的内容不可信。

## 5. 恢复语义（刻意选择）

1. **只增不删**：不清理本机已有节点/规则；
2. **不改本机设置**：分流模式、日志级别保持本机值——恢复别人的配置不该顺手改我的分流策略；
3. **节点重新分配 id**：不沿用对方设备上的标识，也避免撞 id；
4. **同 protocol+address+port 跳过**：沿用 `addNodeSecure` 的去重语义；
5. **规则按 pattern+action 去重**后追加；
6. **凭据重新写入本机 Asset Store**，文件里的明文只在这一次序列化过程中存在于内存。

## 6. 能力边界（必须在 UI 上说清）

- **没有找回**：口令忘了就打不开，不存在后门；
- 安全强度 = 口令强度：`< 8 位`直接拒绝，但仍无法阻止 `password1` 这种弱口令——UI 只做提示，不做假的安全感；
- 口令不能与文件同一渠道传递，否则加密等于装饰（页面提供"复制口令"按钮，并写明"另发一条消息"）。

## 7. 验证

| 项 | 结果 |
| --- | --- |
| 导出 4 节点 / 0 缺失凭据 | `bundle export: nodes=4 rules=0 missingCreds=0` |
| **错口令必须失败** | `wrongPassRejected=true`（`bundle decrypt failed: cipher doFinal failed`） |
| 对口令恢复 | `importOk=true`，4 个同地址节点被正确跳过 |
| **文件里无明文凭据** | `plaintextCredLeak=false`（扫描 `"credential": "..."` 非空） |
| 页面渲染 | 「备份与恢复」两段式：导出（口令 ×2 + 复制口令 + 风险说明）/ 恢复（选文件 → 文件头摘要 → 口令 → 恢复） |

自检入口在开发者面板「备份自检（导出/解密/导入）」，**不依赖系统文件选择器**，可脚本化重跑。

## 8. 遗留

- 「新增节点」这条路径本次没单独构造（同地址节点全部被去重跳过），它走的是与订阅导入相同的 `addNodeSecure` 通道，后者已验证；
- 文件选择器（导出落点 / 导入选文件）未做自动化点击验证，属系统 UI；
- 暂不支持"只导出规则"与"导出到剪贴板"。
