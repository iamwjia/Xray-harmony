# PC15 — 清空所有数据

日期：2026-11-22
范围：`ConfigService.clearAllData()`、`pages/Settings.ets`「危险操作」
设备：HarmonyOS 模拟器（x86_64）

## 1. 为什么单独记

"清空数据"是唯一一个**只能靠用户自己承担后果**的操作。它和"删除一个节点"不是一个量级：后者有二次确认就够，前者一旦点错，节点、凭据、规则、订阅全没了，而且**没有回收站**。

## 2. 删什么、不删什么（文案与实现必须一致）

| 删 | 不删 |
| --- | --- |
| 全部节点 | geo 数据（geoip/geosite 文件） |
| 每个节点的 Asset Store 凭据 | 内核 `libxray` / 已导出的备份文件 |
| 自定义分流规则 | 运行日志缓冲（另在日志页手动清） |
| 订阅记录 + 保存的订阅 URL | |
| 设置：分流模式、日志级别、明示标志 | |

**必须连凭据一起删**：只删节点表会留下一批"没人认领"的 Asset Store 条目，用户以为清干净了，实际密钥还在。

## 3. 实现要点

`clearAllData()` 的顺序是刻意的：

1. **先清凭据、并计数**：节点表一旦清空，`credentialRef` 就找不回来了；先按引用逐个 `SecretStore.remove`，同时统计"应删几条/失败几条"；
2. 再写空存储（逐键写空，不依赖存储层是否有删键能力）；
3. 内存 `config` 回 `createDefaultConfig()`，清掉 `loadFailed` / `rawTextOnLoadFailure` / 迁移标志；
4. `bumpRev()` 通知所有页面重取。

失败处理：**单条凭据删不掉不中断整体**，但把失败数回传给 UI 显示——"看起来清空了、其实还有密钥残留"是最坏的结果。

## 4. 明示标志一起清

`onboardingDone` 被重置为 false 是**有意为之**：数据都清空了，用户等于回到首次使用，"连接前的四要素告知"必须重新出现。实测确认：清空 → 重启 → 点连接 → 明示弹层重新弹出。

## 5. 实测

```
clearAllData: nodes=4 rules=0 subs=0 secrets(node=4 sub=0) failures=0
重启后：loadFromDisk done: nodes=0 rules=0 onboarding=false
首页：未连接 / 当前仅在本机提供代理 / 当前节点（未选择）
点连接：四要素明示重新弹出（等待用户确认）
```

## 6. UI 约束

- 放在设置页**最底部**，单独「危险操作」分组，底色 `danger_subtle`；
- 弹窗里**列出删除清单**（含"不会删什么"），而不是只问"确认清空吗"——后者会被习惯性点掉；
- 破坏性按钮在右侧、`danger` 色，文案是动词「确认清空」而不是「确定」。
