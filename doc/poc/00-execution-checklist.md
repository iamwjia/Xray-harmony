# PoC 一页执行清单（`xray-harmony` 技术可行性判定）

## 0. 执行顺序图

```
第 0 步 前置（0.5~1 人日）
   真机 + 四纪律 + 观测基座 + 设备档位 + 两条版本硬规则
        │  前置未过 ⇒ 后面全部结论无效（假阴性）
        ▼
第 1 步 定路 gate-0a（2.5~4 人日）              ← 最便宜、权重最高
   D(P-27 对象可达) → A(blockedApplications) → B(protect 基线 + 主进程) → C(mark/interface)
        │  ── 决策点 ①：拓扑走 A3 / A1 / 改方案
        │  ⚠️ 若判 A1 强制 ⇒ 先过 P-20 / P-22 / P-24 / P-25，才允许进第 3 步
        ▼
第 2 步 两链并行（链 A 16~20 ∥ 链 B 10~15，两人各带一条）
   链 A（串行，不可拆）        链 B
   P-02 → P-03 → P-04         P-01 → P-20 → P-28
        │  ── 决策点 ②：两链是否全绿
        ▼
第 3 步 合流 J-01（3~5 人日）
   五段：加载 / 数据面 / 统计 / v6 最小用例 / 恢复（必含 D1 划掉 + D2 kill -9 + D5 崩溃）
        │  ── 决策点 ③：J-01 是否通过
        ▼
   通过 ⇒ M1 绿，进 M3 稳定性与合规收口
   不通过 ⇒ 产品不成立（不是降级交付）
```

> **顺序铁律**：`P-01` 与 `P-02` **必须并行启动**（两人各带一条）。串行会把 3~4 周的链拉成 5~6 周，且二者是互不依赖的失败面。

## 2. 三个决策点（每个点只有两种出口）

### 决策点 ① `gate-0a`：拓扑走哪条（第 1 步末）

| | 条件 | 通过 → 做什么 | 不通过 → 做什么 |
|---|---|---|---|
| **通过** | `B-0`（扩展进程内 `protect` 基线）成立，**且** A / B+D / C 至少一条成立 | 按 PC1 §7 表读出拓扑：**A3 可行**（先验默认）或**建议走 A1**（仅靠 C 时）。A3 ⇒ 第 3 步须验跨进程 loopback；A1 ⇒ 该项标 **N/A、不算漏测**。**若判 A1 强制：必须先完成 `P-20`/`P-22`/`P-24`/`P-25` 四项前置，才允许启动 `J-01`**（否则失败无法归因：是拓扑问题还是前置未过） | — |
| **不通过** | `B-0` 不成立（A1/A3 均不成立）**或** A/B/C 全不成立 | — | **属 `B-02` 红灯「无路可退」**（K1 §8.1）：改方案（tun2socks 统一承接出站 / 限制路由捕获范围）或停线，**上报 team-leader + K1 裁决**，不改排期硬上 |

> 判定纪律：只允许 ✅/❌，不接受「部分可用」；时好时坏按 ❌ 记并写复现率（≥3 次中几次失败）。

### 决策点 ② 两链是否全绿（第 2 步末）

| | 条件 | 通过 → 做什么 | 不通过 → 做什么 |
|---|---|---|---|
| **通过** | 链 A：`P-02`/`P-03`/`P-04` 全绿（产物校验八条 + 加载验证 + 三级判据）；链 B：`P-01` 全 L 级通过 + `P-20` 通过 + `P-28` 达标 | 进入第 3 步合流 | — |
| **不通过** | — | — | **分开处置**：链 A 红灯属 **`B-01`「还有路」** ⇒ 换内核编译/运行路径（自研 tun / 换内核）；链 B 红灯属 **`B-02`「无路可退」** ⇒ MVP 无可行形态 ⇒ 停线重估，上报 leader |

### 决策点 ③ `J-01` 是否通过（第 3 步）

| | 条件 | 通过 → 做什么 | 不通过 → 做什么 |
|---|---|---|---|
| **通过** | 五段全绿：① 加载 ② 数据面（HTTPS 返 200）③ 统计（上下行均 >0，且与 ② **同一次请求**）④ **v6 最小用例**（v6 出站 + v6 DNS）⑤ 恢复（**四次**：① 正常关闭 ② **D1 划掉** ③ **D2 `kill -9`** ④ **D5 崩溃**） | **M1 绿** ⇒ 进入 M3（`P-05` + `RG-01`/`RG-02`）；G0 分发决策据此推进 | — |
| **不通过** | 任一段失败（**尤其 ④：即便 ①②③ 全绿也算未通过**；⑤ 四次缺一或该段「反向配置未做」= 该段不成立） | — | **产品不成立，不是降级交付**：暂停商业化 / 收缩为 ArkWeb 容器转发（需产品重新定位），**上报 team-leader**；不得改阈值蒙混 |

> `D3`（低内存回收）/ `D4`（息屏后台被杀）**不进 `J-01` 门禁**，记为 `B-04` 观察项。

## 3. 执行前必须打勾的七件事（缺一项就别开工）

- [ ] 真机可用（`hdc list targets` 非空；**模拟器结论一律不采信**）
- [ ] 调试证书 + Profile 已绑定设备 UDID（换机须重签）
- [ ] **源码钉 tag：`libXray` 一律 `v26.7.28`，禁止 main / HEAD**（main 的 `go.mod` 要求 go 1.27.1 → 报 `module requires go >= 1.27.1`，极易被误判成工具链问题）
- [ ] **构建路线已选定：A（单次构建合并为单一 `.so`，默认）或 B（分库 + 严控加载顺序，仅兜底）**；选 B 必须在记录里写「已知违反单 runtime 规则」，该路线下崩溃先按此归因再查别处
- [ ] 至少 1 个可用 **VLESS/TLS 或 VMess 节点**，具备 **v4 与 v6 双栈出口**（节点不通会污染全部判定）
- [ ] 网络环境可切换 **仅 v4 / 双栈**（IPv6 项另需 **仅 v6**，见 PC4 §2.6）
- [ ] `hdc` + hilog 采集链路跑通（能同时留存 hilog、进程快照、计数器采样三份原始数据）

## 4. 四条不可违反的记录纪律

1. **二值判定**：只能写「通过 / 不通过 / 无法判定」；「无法判定」**必须写明缺什么**（缺设备档位 / 缺环境 / 缺观测手段），否则退回记「待执行」。
2. **受控失败对照（判据自检）**：凡有明确二值判据的实验，必须含至少一个「已知应当失败」的对照；**对照也"通过" ⇒ 该实验此前结论一并作废**。方法见 [README.md](./README.md) §3。
3. **边界触发（边界自检）**：静默通过不算通过——必须构造一个「能撞到边界」的输入并确认如实报错。撞边界输入清单见 [README.md](./README.md) §5。
4. **数值三档 + 性能不设通过线**：数值必须标 `实测基线` / `建议初值（工程判断）` / `待填（来源）`；**性能项（吞吐、时延、内存增长）不设通过线**，只记基线并标「基线，非阈值」——是否可接受由 `J-01` 之后的 `B-04` 结合真实使用判断。未实测数字**不得回写进需求指标**。

## 5. 交付前自查（**逐文件可扫，不必读完全文**）

> 用途：评审者拿到任意一份记录/汇总，扫这四条即可判断"这份东西能不能信"。**任一条不过，对应结论不认。**

| # | 自查项 | 怎么扫（机械判据） | 不过什么 |
|---|---|---|---|
| **S-1** | **「N 次 / N 项」必须紧跟枚举**，且**正文 / 记录模板 / 汇总表用同一套标签** | 全文搜 `次`、`项`、`条`；每个数量词后面 3 行内必须有可数清单（如"四次：① ② ③ ④"）；再把三处的标签逐字比对（例：正文四次 = ① 正常关闭 ② D1 划掉 ③ D2 `kill -9` ④ D5 崩溃；记录表若写"三项"或标签不同名 ⇒ 不过） | 数量对不上 ⇒ **汇总表不可信**，该段结论作废（典型事故：正文写四次、记录写五次、汇总写三项） |
| **S-2** | **每个二值判据都配受控失败对照**，且记录表有「**反向配置结论：通过 / 失败 / 未做**」格 | 搜每段的判据行，确认存在对应"反向配置（必须做）"项；再看记录表该格是否已填三值之一 | 填「**未做**」⇒ **该段不成立**，按不成立计入汇总（不是"跳过"、也不计为通过） |
| **S-3** | 数值三档已标 | 搜数字与阈值，确认标了 `实测基线` / `建议初值（工程判断）` / `待填（来源）`；性能项（吞吐 / 时延 / 内存增长）**只允许标「基线，非阈值」** | 未标 ⇒ 缺陷；性能项给出"通过线" ⇒ 违规（等于用未验证数字验收未验证实现） |
| **S-4** | 结论只取三态，且"无法判定"写明了缺什么 | 搜「部分通过 / 基本可用 / 大概 / 应该」等模糊词；搜每个「无法判定」是否同时写明缺设备档位 / 缺环境 / 缺观测手段 | 模糊表述 ⇒ 退回重记；未写缺什么 ⇒ 改记「待执行」（不得把"没做"伪装成"判不了"） |
