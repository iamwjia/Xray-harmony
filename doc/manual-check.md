# 手动验收清单

> 自动化跑不到的东西都在这里。**每条都有判据**，勾选时只看判据，不看“感觉差不多”。
> 三类标记：
> - `[脚本]` 一键验证已覆盖，不用手点（`powershell -File scripts\verify.ps1`）
> - `[设备]` 必须在模拟器/真机上点或看
> - `[人眼]` 必须有人看画面（截图后自己判断，Agent 看不到图）

## 1. 触摸交互 `[设备]`

判据统一是：**手指按下后 100ms 内必须有可见变化**；没有变化 = 退回“鼠标式”设计。

### 1.5 行内手势（左滑 / 右滑 / 长按 / 下拉）

**判据：动作块必须整块可点，且颜色能区分危险程度；滑开之后不执行任何动作就滑回去，必须能收起。**

- [ ] **节点行左滑** → 行右端露出两块：蓝底白字「测连通」、红底白字「删除」，各带图标
- [ ] **节点行右滑** → 行左端露出一块紫底白字「编辑」
- [ ] **滑回去 / 点空白处** → 收起，行恢复原状（不执行任何动作）
- [ ] **执行任一动作** → 动作生效，且露出的块自动收起（不留在张开状态）
- [ ] **订阅行左滑** → 露出蓝底「更新」、红底「删除」
- [ ] **右滑节点行** → 露出「编辑」与「复制」；点复制后弹警告级提示（含凭据），粘贴到别处应是 `vless://…` / `trojan://…` / `ss://…` / `vmess://…` 之一
  - 注：复制不再挂在“整行长按”上——长按会与右侧拖拽抓手抢手势（实测：按住抓手拖动会先触发长按）
- [ ] **拖动排序** → 按住行右侧的 `≡` 抓手上下拖：松手后列表顺序变化，顶部出现「已上移/下移 N 位」
- [ ] **抓手与点行不打架**：点抓手不会选中行；点行（非抓手区）不会启动拖动
- [ ] **节点列表下拉** → 出现刷新指示并重新读盘（计数不变，说明数据没丢）
- [ ] **订阅列表下拉** → 依次更新过期订阅，结束时顶部出现「已更新 N 个订阅」
- [ ] **下拉与滚动不打架**：列表已在顶部时下拉才触发刷新；列表停在中间时下拉只是滚动回顶部

### 1.0 术语对应的界面位置（按 App 实际显示写）

**先看页面标题确认位置**：节点列表页顶部写「节点列表」，订阅管理页顶部写「订阅管理」+ 右侧计数「N 个」。

```
【节点列表】页 —— 一行（NodeRow）长这样，宽约 328vp：

┃ ✓   香港-01   香港            ⋯
█     [vless] hk01.example.com     :443
↑     ↑         ↑                ↑
竖条  对勾/空心圈  第二行小字       操作菜单
      ↑
   第一行：节点名（15fp）

- 「竖条 / 对勾」是选中态（三重编码：竖条+对勾+字重）
- 第二行是 `协议色标 + 地址:端口`：协议名带底色小块（vless 蓝 / vmess 紫 / trojan 青 / ss 琥珀），后接地址，端口右对齐
- 「香港」是分组 chip，挂在**第二行右侧**，没有分组就不显示
```

```
【订阅管理】页 —— 一行长这样：

10.0.2.2:8000                      ⋯
2 个节点 · 更新于 11-22 14:03
↑                                ↑
订阅名（导入时取 URL 的 host）      操作菜单（立即更新 / 删除）

- 过期时第二行变警告色并改写成：「超过 7 天未更新」
- 若从未更新过：`尚未更新`
- 列表为空时看到的是「还没有订阅」+ 一句引导，**此时没有订阅行可测**
```

| 清单里的说法 | 界面位置（页面标题） | 实际显示 |
| --- | --- | --- |
| **节点行** | 「节点列表」页的每一行 | 见上图；名称 + `协议色标 + 地址:端口` + 分组 chip + `⋯` |
| **订阅行** | 「订阅管理」页的每一行（入口：设置 →「订阅管理」→「管理」） | 见上图；订阅名 + `N 个节点 · 更新于 …` + `⋯` |
| **分组 chip** | 「节点列表」页顶部（只有存在分组时才出现） | 「全部」「香港」这类胶囊 |
| **日志级别 chip** | 「运行日志」页顶部筛选行（入口：设置 →「运行日志」→「查看」） | 「全部 / INFO / WARN / ERROR / 刷新 / 清空」 |
| **诊断行** | 「运行日志」页说明下面那一行 | 「当前代理地址 …」/「最近一次代理地址 …（已断开）」/「暂无代理地址记录…」 |
| **节点操作菜单** | 节点行右侧 `⋯` 点开 | 编辑 / 测连通性 / 上移 / 下移 / 删除 |
| **订阅操作菜单** | 订阅行右侧 `⋯` 点开 | 立即更新 / 删除 |

> 注意：**「节点行按下」指的是整行（`⋯` 之外的部分）**。按 `⋯` 是打开菜单，不是选中行——这两个命中区是兄弟，互不嵌套。

- [ ] **节点行按下** → 底色变化（未选中变灰 `bg_chip`，选中变浅蓝 `accent_subtle`），抬起恢复
- [ ] **订阅行按下** → 同上；且同一时刻只有一行变色
- [ ] **分组 chip / 日志级别 chip** → 有系统按钮的回弹/变暗
- [ ] **导入框输完按回车** → 直接开始导入，不需要去点被键盘挡住的按钮
- [ ] **添加规则输入框回车** → 直接添加
- [ ] **备份口令框回车** → 导出/恢复开始
- [ ] **首页代理地址长按 500ms** → 出现「已复制」，剪贴板内容严格等于 `127.0.0.1:<port>`
- [ ] **日志页诊断行长按** → 同上
- [ ] **设置页「每6/12/24小时/每周」** → 窄屏下换行，不被压扁或截断
- [ ] **节点操作菜单** → 宽度约 180vp，五项完整可读（编辑/测连通性/上移/下移/删除），首行「上移」灰、末行「下移」灰

## 2. 数据与状态 `[设备]`

- [ ] **重启不丢数据**：加节点 → 强制停止 → 重启 → 节点仍在（`nodeStore load: rawLen>0`）
- [ ] **首次明示只弹一次**：确认后重启，点连接不再弹
- [ ] **清空数据**：设置 → 清空 → 重启后节点 0、规则 0、明示重新出现
- [ ] **备份→恢复**：导出 → 清空 → 恢复 → 节点回来；**错误口令必须失败**
- [ ] **删除订阅不删节点**：确认弹窗写清“节点保留”，删后节点数不变
- [ ] **节点连通性**：菜单「测连通性」→ 提示条给出「可达 N ms」或具体不可达原因

## 3. 数据面（必须真机）`[设备]`

- [ ] **`202` 是否消失**：点连接 → 状态文件 `vpn_state.json` 里不再是
      `{"state":"error","code":202,"msg":"Non-system applications use system APIs"}`
      （这是决定产品可行性的一条）
- [ ] **转发生效**：连接后从设备访问外网域名成功；服务端日志出现 `connection opened`（`accepted` 不算）
- [ ] **DNS 走隧道**：`tcpdump` 观察 53 端口流量走 tun，而不是本地直连
- [ ] **断开顺序**：断开后 tun 已销毁、无残留（`ip link` 里没有 vpn-tun）
- [ ] **失败注入**：把 socks 端口改错 → 状态进入 `error`，且 **tun 已被销毁**（不留黑洞）

## 4. 深色模式 `[人眼]`

每页截一张深色图，只看四件事：**有没有白块、文字是否可读、选中态是否可辨、横幅是否刺眼**。

- [ ] 节点列表（选中行 / 空态 / 分组 chip）
- [ ] 节点编辑（输入框边界）
- [ ] 分流规则
- [ ] 运行日志
- [ ] 设置
- [ ] 订阅管理
- [ ] 备份与恢复
- [ ] 开源许可

## 5. 文案与诚实性 `[人眼]`

- [ ] 首页不出现 `SOCKS` / `freedom` / `内核直连` 等实现词（`DevPanel` 豁免）
- [ ] 首页明确显示「系统 VPN：已接管 / 未接管 —— 原因」
- [ ] 连接失败时给的是人话（不是 `202` 裸码）
- [ ] 长按类功能都有可见提示，不只在读屏里

## 6. 一键验证覆盖了什么 `[脚本]`

