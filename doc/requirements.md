## 0. 阅读指引（三分钟版本）

1. **产品是什么**：HarmonyOS NEXT 上的 Xray 客户端，把 Xray-core 以 `.so` 形式同进程加载，通过系统 `VpnExtensionAbility` 接管全设备流量（形态 A），或以应用内局部代理方式提供受限通道（形态 B，V1）。
2. **MVP 唯一目标**：验证 **J-01** ——「Xray 内核以 so 同进程加载 + 经 tun2socks 路径跑通 tun 数据面」是否成立，并交付一个能在真机上闭环使用的最小客户端。
3. **三条不能妥协的红线**（互不替代，各自独立验收）：`UI 状态不说谎`（FR-13）／`终止可感知`（FR-14）／`已连接但实际不通可检出`（FR-15）。
4. **一个总原则**：**fail-closed** —— 失败即关闭，而非失败即放行。它有一个**已知违背面**（进程终止 → 系统撤销 VPN → 流量恢复直连），本文件不掩盖。
5. **不承诺的事**：开机自启、后台常驻、零中断热切换、进程级 kill switch、默认状态下 IPv4 与 IPv6 同等保护 —— 原因与依据见 §2「承诺边界」。

## 1. 产品定位与目标用户

### 1.1 定位

**定位依据（来自竞品分析，R3）**：HarmonyOS 上已有跑通的 Xray 客户端（Hey 被 Xray 官方 README 收录），它证明了「**技术可行**」，但没有证明「**产品可用**」——只发源码不发 HAP、单人维护、40 star，且**主动放弃大众用户**（不内置任何服务器/订阅源/规则集，"Bring your own server"）。因此本项目的差异化空间不在"能不能跑通"、也不在"比谁快"，而在「**是否把它做成一个普通用户能用的产品**」。**该差异化主张属 V1 待定项（§7 U-5），不阻塞 MVP。**

**定位约束（必须随定位一起读）**：

| # | 约束 | 依据 |
|---|---|---|
| C-1 | **不以「首款/首发」作定位主张**：HarmonyOS 上已有先于本项目的 Xray 客户端（Xray 官方 README 收录的 Hey） | leader 裁定；R1 §2.4/§5.4 |
| C-2 | **不以「无需配置的全局加速器」作定位**：本产品是配置驱动型工具，核心用户理解订阅、节点、分流的概念 | R1 §3.2 |
| C-3 | **不以「隐私绝对安全」作定位**：本平台无进程级 kill switch，进程终止后流量恢复直连（见 FR-17 明示义务） | R2 §3.2/§4.2；leader 裁定 |
| C-4 | **公开上架路径存在实质性合规障碍**，产品形态与分发方式必须由用户先决策（见 §7） | R2 §6.2 |

### 1.2 目标用户

| 用户类型 | 特征 | 对本产品的关键诉求 |
|---|---|---|
| U1 自建节点用户 | 有自己的 VPS/服务端，使用 VLESS/REALITY 等协议 | 协议与传输覆盖要全、能导入自己的配置、不被客户端"阉割" |
| U2 订阅驱动用户 | 从服务商拿订阅链接，节点多、切换频繁 | 导入即用、切换快、失败能看懂原因 |
| U3 隐私敏感用户 | 在公共网络环境工作，关注流量是否泄漏 | 知道什么时候"已保护"、什么时候"没保护"（IPv4/IPv6、分应用覆盖） |
| U4 内测/自用分发场景的技术团队 | 通过调试安装或企业内部应用分发使用，不追求上架 | 可复现的构建、可导出的诊断、许可合规清晰 |

### 1.3 典型使用场景

| # | 用户 | 场景 | 目标 | 当前痛点（调研依据） |
|---|---|---|---|---|
| S1 | U1/U2 | 日常办公：把新订阅导入 → 选节点 → 一键连接 → 全程访问海外文档/代码仓库 | 一次配置长期可用，切换节点不折腾 | 多数客户端在**通道未建立**时仍显示"已连接"，用户无法判断是节点问题还是应用问题（R2 §9.5：无 VPN 专用状态回调，仅 `BEARER_VPN` 间接信号） |
| S2 | U2 | 通勤路上 Wi-Fi ↔ 蜂窝频繁切换 | 切换后自动恢复，不需要手动重连 | 网络切换后隧道重建失败但 UI 不刷新；重启应用后配置丢失需重选（R2 §7 #22 网络感知能力可用但无自动恢复约定） |
| S3 | U3 | 首次使用：需要判断"我到底被保护到什么程度" | 明确知道 IPv4/IPv6、分应用、进程终止三类边界 | 平台默认 `isIPv6Accepted=false` ⇒ **v6 默认不进隧道**（R2 §9.6）；分应用上限 64/256 且两列表互斥（R2 §3.6）；进程退出即停 VPN（R2 §3.2）—— 这些事实用户从界面上完全看不出来 |
| S4 | U4 | 团队内部试用：把判定为"能用/不能用"的结论带回去 | 出错时能导出可诊断的信息 | 崩溃与断连原因不可导出、日志混杂在系统日志里（R2 §7 #23 日志能力可用但需自建导出与脱敏） |

## 2. 承诺边界与 fail-closed 原则（**本文件最重要的一节**）

### 2.1 承诺边界（不承诺项 + 原因 + 依据）

| # | 不承诺 | 原因（平台事实） | 依据 | 替代承诺 |
|---|---|---|---|---|
| B-1 | **不在进程终止后继续保护流量** | 官方明确「调用 `startVpnExtensionAbility` 接口的**应用进程退出时**，系统会主动停止 VPN」⇒ VPN 停止即 tun/路由撤销 | R2 §3.2、§4.2 | 启动即恢复（FR-16）+ 首次连接一次性明示（FR-17） |
| B-2 | **不提供进程级 kill switch** | `isBlocking` 在 VPN 停止后的残留语义官方**未定义**；无官方 kill switch 概念 | R2 §9.6；`VQ-21`/P-26 | 仅在进程存活期间保证 fail-closed（§2.3）；明示义务见 FR-17；进程存活期内由 FR-36 探测止损 |
| B-3 | **不支持开机自启** | `StaticSubscriberExtensionAbility` 仅对系统应用开放，且需设备预置 `install_list_capability.json` | R2 §4.4、§7 #13 | 桌面卡片/快捷方式一键启动（FR-27，V1）+ 启动即恢复（FR-16） |
| B-4 | **不承诺后台永久常驻** | 长时任务类型表**无 vpn 类型**；`dataTransfer` 有"首次进度更新 ≤10 分钟且需实况窗"约束，`taskKeeping` 需 restricted 权限 + ACL | R2 §4.1、§4.2 | 必须申请长时任务（FR-11）+ 保活失败时以"启动即恢复"兜底（FR-16），**稳定运行时长不作 SLA** |
| B-5 | **不承诺节点切换零中断** | 控制面无整体配置重载、无"改单个 outbound 目标地址"原语，无连接迁移 | R1 §4.2 | 快速重启内核（毫秒~百毫秒级），切换过程 UI 显式呈现"重连中"（FR-09、FR-13） |
| B-6 | **默认不提供 IPv6 出网（但也不泄漏）** | 官方默认 `isIPv6Accepted=false`，`addresses` 未配 v6 地址则 v6 不进 tun。**但"不接管"≠"不泄漏"**：正确做法是**恒接管 + 内核侧阻断**（`block ::/0` 秒拒），使默认状态既不泄漏也不提供 v6 出网，应用自然回落 IPv4 | R2 §9.6；R3 §9 K11/K5/K10 | 默认策略：**IPv6 已接管并阻断，流量走 IPv4**；如需启用 IPv6 代理，由用户在设置中显式开启（FR-19/FR-20） |
| B-7 | **不承诺"通知栏那条不能被清掉"** | 用户删除长时任务通知 → 系统自动停止长时任务 | R2 §4.1 | 首次开启时明示该事实（FR-17 三要素之外的第 4 句） |

### 2.2 fail-closed 原则（顶层 NFR 原则，NFR-11）

> **默认值必须站在"不漏"这一侧；任何可能导致流量绕过的配置，只能是用户显式选择的结果，不得作为默认行为。**

适用面（五项，缺一即该面不满足）：

| # | 适用面 | 默认行为 | 依据 |
|---|---|---|---|
| F-1 | IPv6 | `isIPv6Accepted=true` 且满足四条件 | R2 §9.6；leader 定案 |
| F-2 | DNS | 默认走隧道内解析（加密 DNS 或内核内置 DNS），**绝不默认回落系统 DNS** | R1 §3.1 dns；R2 §3.1 dnsAddresses |
| F-3 | 分应用分流 | 默认**全局代理**；白名单/黑名单是用户主动配置的结果 | R2 §3.6 |
| F-4 | 分流规则 | 默认**未知域名走代理**（"未知走直连"在大陆网络环境下等价于默认泄漏） | R1 §3.1 routing |
| F-5 | 故障降级 | 内核崩溃/隧道中断时**阻断流量**，不得"智能切换"到直连 | leader 定案 |

**已知违背面（必须与原则同时陈述）**：B-1 —— 进程终止导致系统撤销 VPN 时，流量将恢复直连。这不是实现缺陷，是平台行为；本产品只能在**进程存活期间**保证 fail-closed。

### 2.3 「fail-closed 与进程终止即直连」不矛盾（供 Z1 机械核对）

二者约束对象不同：
- **fail-closed** 约束的是**应用内故障处理**：隧道断、节点不可达、内核异常、DNS 失败时，选择阻断而非直连；
- **「进程终止 → 系统撤销 VPN → 流量恢复直连」** 是**平台行为**，不属应用可裁决范围。

因此本文件不存在自相矛盾；但读者必须同时看到两者，否则会误以为本产品是 kill-switch 类工具。

## 3. 范围边界与分期

### 3.1 MVP（必须能独立闭环交付）

**MVP 的唯一目标**：验证 **J-01** 并交付可用最小客户端。J-01 定义 =「Xray 内核以 **so 同进程加载** + **经 tun2socks 路径**跑通 tun 数据面」，判定须含 **v6 最小数据面用例**（同机同批，避免"P-01 全绿但 v6 漏流量"的假绿灯）。

**MVP 闭环判定（缺一即不闭环）**：

```
安装 → 首次授权引导 → 导入订阅 → 选节点 → 建立隧道 → 应用可见"已保护程度"
  → 断开/被杀 → 重开 → 一键恢复 → 诊断可导出
```

**MVP 切分依据（受平台硬约束影响，逐条引依据）**：

| 决策 | 依据 |
|---|---|
| 形态 A（tun）为 MVP 唯一形态，形态 B 出 MVP | B 不依赖 tun、也不验证内核链路，放进 MVP 只会分散验证资源；其价值（无权限侵入）在 A 跑通前无意义（leader 裁定 + R2 §3.4） |
| 不做开机自启 | 平台不支持（R2 §4.4） |
| 节点切换用"快速重启内核"而非热切换 | 控制面无 reload 原语（R1 §4.2） |
| 性能指标全部留待实测回填 | R1 §5.3 明确禁止引用"业界量级" |
| 分应用分流采用"免权限配置模式" | 三方无法枚举已安装应用（R2 §9.5），交互只能预置表 + 手输 |

### 3.2 V1（MVP 闭环成立后启动）

启动前置条件：J-01 成立 **且** 真机长稳观测（P-07/长时任务）不再出现"使用中断连"的阻塞级问题。

V1 范围：自定义路由规则编辑（FR-07）、流量统计（FR-25）、订阅定时更新（FR-26）、桌面卡片一键启动（FR-27）、多语言（FR-33）、无障碍（FR-34）、**形态 B 局部代理模式**（FR-32）、差异化主张落地（待 R3 + 用户决策）。

### 3.3 后续期次（依赖外部条件，不承诺）

| 期次 | 内容 | 启动前置 |
|---|---|---|
| P2 | 开机自启 | 仅在获得系统级合作/预置能力时，否则永久不启动 |
| P2 | 多 VPN 共存（`generateVpnId`，API 20+，仅 IPv4） | 目标机型 API ≥20 且用户确有需求（R2 §3.1） |
| P2 | 远程增量更新预置应用表 | 安全设计（签名 + 防回滚 + fail-closed）评审通过（见 FR-30） |
| P2 | `taskKeeping` 高优保活 | ACL 白名单获批（restricted 权限，R2 §4.2） |

### 3.4 G0 决策闸（**全文仅此一处定义，其余引用**）

G0 = 「**P-01 技术结论 × 分发策略**」二维判定。表内不设"假兜底"——MVP 范围内没有形态替代方案。

| P-01 结论 | 分发策略 = 自用/调试（≤100 台） | 内测分发（企业内部） | 公开发行（AppGallery） |
|---|---|---|---|
| **成立**（so 加载 + tun2socks 数据面 + v6 最小用例通过） | ✅ MVP 交付，形态 A 为默认模式 | ✅ 可交付，需企业分发资格（3~8 工作日） | ⚠️ 技术可行但**合规路径存疑**，需 IP-VPN 类许可（1~4 个月） |
| **部分成立**（如最小 so 通但数据面不通 / v6 用例失败） | ⛔ **停线重估**，不给降级出口 | ⛔ 停线重估 | ⛔ 停线重估 |
| **不成立** | ⛔ **MVP 无法交付 → 项目重新定义并上报 team-leader** | 同左 | 同左 |

> 说明：G0 的产出不是"A 或 B 二选一"，而是「**形态组合与默认模式**」——形态 A 为默认模式且必交付；形态 B 属 V1，不构成 A 的兜底。

### 4.6 三条红线与生命周期诚实性（FR-13 ~ FR-17）

> 三条红线**互不替代**、编号独立、验收独立、不得做成"任一通过即可"。

**FR-13 UI 状态与真实隧道状态严格一致（红线1）** ｜ 共用 ｜ P0 ｜ 依据 R2 §9.5
- Given 任意时刻
  When 渲染连接状态
  Then UI 状态由真实隧道状态**单向派生**，禁止乐观置位；`BEARER_VPN`（`netCapabilitiesChange`）**仅表示默认网络承载为 VPN，不等于我方隧道健康**，禁止单独以它置"已连接"
- Given 系统侧被动停止 VPN（非用户在我方 UI 内点击断开）
  When 状态变化发生
  Then ≤N 秒内 UI 更新为"未连接"（N 由 VQ-19 回填：前台上限 5s、后台 15~30s；事件为主 + 3s 兜底轮询）
- Given 冷启动
  When 应用启动
  Then 以**实际探测结果**为准，不得以缓存的"上次为已连接"直接渲染为已连接
- **负向验收**：注入隧道异常（断节点/断网/后台停隧道），UI **不得**仍显示"已连接"

**FR-14 终止可感知（红线2）** ｜ 共用 ｜ P0 ｜ 依据 leader 裁定 + R2 §3.2
- Given 上次运行以"用户划掉 / 系统回收 / 崩溃"终止
  When 用户下次打开应用
  Then 首屏 ≤2 秒内显示"上次连接已于 <时间> 中断（原因：用户终止 / 系统回收 / 异常退出）"，并提供"一键恢复"入口
- **负向验收**：用户划掉应用后，桌面卡片、通知栏、任何界面元素**不得**残留"已连接/传输中"的误导状态

**FR-15 事实不通可检出（红线3）** ｜ 共用 ｜ P0 ｜ 依据 R2 §9.5；P-19
- Given UI 显示"已连接"
  When 数据面实际不可用（对端无响应 / 路由错误 / 出站失败）
  Then ≤N 秒内（同 FR-13 的 N 口径）转为"已连接但无流量"的独立状态，并给出下一步动作（切换节点 / 查看诊断）
- **负向验收**：构造"承载事件正常但隧道已死"的场景，UI **不得**维持"已连接且正常"的表述

**FR-16 中断后的恢复体验** ｜ 共用 ｜ P0 ｜ 依据 leader 裁定
- Given 存在可用节点与生效配置，但隧道未建立
  When 用户打开应用
  Then 首屏展示"一键恢复连接"（含上次节点名与协议），点击后 ≤ 实测基线（P-24 回填）完成建连
- Given 恢复失败
  When 失败发生
  Then 给出分类错误（网络不可用 / 节点不可达 / 2203002 冲突 / 权限未授予 / 配置无效），每类均提供对应处置入口

**FR-17 首次连接一次性明示（忠诚披露）** ｜ 共用 ｜ P0 ｜ 依据 §2.1
- 内容四要素（**同屏同时可见，不得折叠进"详情"**）：
  1. 应用被系统或用户终止时，代理会停止，**流量将恢复直连**；
  2. 本应用**不提供进程级 kill switch**；
  3. 当前 IPv6 策略与状态（**默认口径**：「IPv6 已接管并阻断，当前流量走 IPv4；如需启用 IPv6 代理，请在设置中显式开启」；已开启时显示「IPv6 代理已启用」）；
  4. 长时任务通知被删除时，保活会停止。
- Given 首次成功连接前
  When 用户点击连接
  Then 弹出**模态确认**，用户必须主动点击"我已了解"才能继续；**不得**预勾选"不再提示"、**不得**提供跳过路径；背景点击 / 返回键 / 手势返回均不得关闭模态（三种绕过尝试各一条用例）
- Given 用户已确认过一次
  When 后续连接
  Then 不再重复出现；且**不存在**"重新显示首次提示"的开关（防止运营侧关掉披露）
- 验收：卸载重装后重现；清除应用数据后重现；文案不得含"不影响使用""仅偶发"等淡化表述

### 4.7 网络与 IPv6（FR-18 ~ FR-20）

**FR-18 网络切换后自动重连** ｜ A ｜ P0 ｜ 依据 R2 §7 #22
- Given 已连接状态下发生 Wi-Fi ↔ 蜂窝切换 / 短时断网（≤30 秒）
  When 网络恢复
  Then 应用自动重建隧道（无需用户手动操作），并在重建期间 UI 显示"重连中"；重建成功后状态与诊断页同步刷新
- Given 切换后重建失败
  When 连续失败 ≥2 次
  Then 转为"需用户介入"状态并给出原因分类，不无限重试
- **验收必须包含**：切换后 **IPv6 路由与 IPv6 DNS 必须重建**（路由重建时最易丢 `isDefaultRoute:false` 等字段，见 P-23）

**FR-19 IPv6 纳入隧道（四条件）** ｜ A ｜ P0 ｜ 依据 R2 §9.6；leader 定案
- 四条件**同时满足**才算"已纳入 IPv6"，缺一即判**未纳入**：
  1. `isIPv6Accepted = true`；
  2. `VpnConfig.addresses` 含 IPv6 类型地址；
  3. `routes` 覆盖 v6 默认路由（`::/0`，配 `gateway.address=''` + `hasGateway:false` + `isDefaultRoute:false`，实现依据 D-25）；
  4. 内核（Xray）侧具备 v6 出站能力（由 D1 承接，需求侧只要求可验证）。
- Given 四条件均满足
  When 在 IPv6-only 与双栈环境各测一组
  Then v6 流量进入隧道且可正常出网；DNS（v6 查询）走隧道内解析
- Given 任一条件不满足
  When 验收
  Then 判为"未纳入 IPv6"，按 FR-20 三处明示，并按 §8 的弱化路径处理（**需 leader 批准**，不自动执行）
- **反证测试（必测）**：逐一关闭任一条件（flag / v6 地址 / v6 routes / 内核 v6 出站），诊断页必须相应显示"未保护"；任一出现"实际未保护但显示已保护"即判不通过
- **关闭 IPv6 的正确实现方式（重要，与直觉相反）**：即便产品选择"不支持 IPv6"，也**必须恒接管** v6（`isIPv6Accepted=true` + 单条 `::/0`），再在**内核侧**按开关处置——关闭态：DNS `queryStrategy=UseIPv4` + 路由 `block ::/0` 秒拒（逼应用回落 v4）；开启态：转发至节点。**"不接管 v6"不等于"不泄漏"**（依据 R3 §9 K11）。因此本需求的降级路径不是"关掉 `isIPv6Accepted`"，而是"接管 + 内核侧阻断"，唯一例外是平台完全无法下发 v6 路由（P-23 结论）时才三处明示（FR-20）
- **泄漏判定方法（验收必须按此执行）**：用**分协议出口 IP 检测**（`api-ipv4.ip.sb/ip` 与 `api-ipv6.ip.sb/ip`）判定，出口归属为本地运营商即为泄漏；**不得**以 `/proc` 路由表作为判据（VPN 路由进入独立策略路由表，主表看不到 `::/0` 属正常现象，依据 R3 §9 K10）
- **v6 路由写法（实现判据，供 D1 引用）**：`gateway:{address:''}` + `hasGateway:false` + `isDefaultRoute:false`（即使目标是 `::/0` 也填 `false`）；用 `gateway:{address:'::'}` + `isDefaultRoute:true` 会被系统**静默丢弃**，导致 v6 从物理口直出（依据 R3 §9 K5；该写法首现于 `x4h`，Hey 在真机复现验证）

**FR-20 IPv6 保护状态可见** ｜ A ｜ P0 ｜ 依据 leader 裁定
- Given 任意连接状态
  When 用户查看诊断页
  Then 有**独立状态行**「IPv6 保护：已启用 / 未启用（当前仅保护 IPv4）」；未启用时用警示样式并可点击查看原因
- 三处必须同时存在：诊断页状态行 + 首屏（连接卡片）+ 首次连接明示（FR-17 第 3 要素）

### 4.8 分应用分流（FR-21、FR-30）

**FR-21 分应用分流（免权限配置模式）** ｜ A ｜ P0 ｜ 依据 R2 §3.6、§9.5
- 能力层表述：基于 `VpnConfig.trustedApplications` / `blockedApplications` 的 **IP 层**应用级分流（与应用是否使用系统 http 栈**无关**）
- **模式互斥**：全局只能处于「白名单模式（仅代理所选应用）」或「黑名单模式（排除所选应用）」之一；切换模式时清空另一模式列表并二次确认。**验收禁止出现"同时支持白名单与黑名单"**
- 上限（官方明文，按 API 档位）：**≤64 个应用（API 12~22）/ ≤256 个（API 23+）**；达上限时 UI 提示当前上限与 API 档位并**禁用新增**；**禁止**"已添加但未生效"
- Given 用户进入分应用配置
  When 选择应用
  Then 三条路径至少两条可用：① 内置常见应用表中选择 ② 按名称/包名搜索内置表 ③ 手动输入包名；且入口处明示"**应用名来自内置常见应用表，未收录的应用请手动输入包名**"
- Given 内置表未收录某包名
  When 列表中展示
  Then 显示「未知应用（包名 xxx）」，不得显示空白或伪装为系统应用名
- Given 某条目对应包名已不存在（无法查询签名/安装状态，见 VQ-18）
  When 用户点击该条目
  Then 给出「疑似失效：请确认该应用仍已安装，必要时重新选择」提示（**不承诺**自动检测签名变化或卸载）
- **与 FR-39 联动（重要）**：分应用名单属于 `VpnConfig` 的**接管面字段**，**勾选/取消任一应用都会触发断连重建**；因此每次保存前必须二次确认并明示"将断开当前连接"。验收时不得把"断连"判为缺陷

**FR-30 预置应用包名表（覆盖量与更新机制）** ｜ A ｜ P0 ｜ 依据 R2 §9.5 缺口
- Given MVP 交付
  When 用户打开分应用配置
  Then 内置表至少覆盖 N 个常见应用（N 待回填，VQ-24；「表为空/覆盖不足」**算我方缺陷，不得归因平台**）
- Given 采用远程增量更新（**MVP 默认不开启**，是否开启需 leader/用户裁决）
  When 更新
  Then 必须同时满足四条，缺一即视为未实现安全更新：
  1. 更新包由发布密钥签名，公钥内置应用（不联网拉取公钥）；
  2. 单调递增版本 + 本地记录已接受最高版本，拒绝降级包（防回滚攻击）；
  3. 校验失败/版本回滚/网络异常 → **保留旧表 + 用户可见告警**，禁止使用空表或全量放行；
  4. 更新仅允许追加/修正映射条目，**不得下发任何路由或代理决策**；来源域名变更视为版本变更（走发版）

### 4.9 可诊断性与合规（FR-22 ~ FR-24、FR-29、FR-31）

**FR-22 连接诊断（分步定位）** ｜ 共用 ｜ P0 ｜ 依据 R1 §4.1；R2 §7
- Given 用户打开诊断页
  When 执行一次诊断
  Then 按顺序给出五项结论（每项：通过/失败 + 原因 + 建议动作）：① 内核加载（so 与运行时）② 内核配置合法性 ③ 隧道建立（tun fd 与路由）④ 出站连通（目标可达性）⑤ DNS 解析与 IPv6 保护状态
- Given 某项失败
  When 展示
  Then 不暴露敏感信息（订阅 URL、UUID、私钥全文），只显示脱敏片段

**FR-23 日志查看与导出（脱敏）** ｜ 共用 ｜ P0 ｜ 依据 R2 §5、§7 #23
- Given 用户进入日志页
  When 查看
  Then 可按级别过滤（DEBUG/INFO/WARN/ERROR），保留最近会话日志
- Given 用户点击"导出诊断包"
  When 导出
  Then 生成包含"日志 + 配置快照（脱敏）+ 设备与版本信息"的单个文件并由用户自行分享；**MVP 不上传任何数据**

**FR-24 崩溃诊断（上次异常退出）** ｜ 共用 ｜ P0 ｜ 依据 leader 裁定；R1 §2.4 P8；R2 §7 #23
- Given 上次会话发生崩溃（包括扩展进程内的内核 panic 带走整个扩展进程；主进程 ↔ 扩展进程有隔离，内核 ↔ 数据面引擎无隔离）
  When 用户再次启动
  Then ≤3 秒内呈现「上次异常退出」（时间、场景、最后一步操作、崩溃栈摘要），并提供"导出诊断包"入口
- 该能力为**必选**（扩展进程内无隔离兜底，且扩展进程崩溃后主进程只剩"感知"能力），不得作为可选优化项

**FR-29 许可与来源声明（MPL-2.0 义务）** ｜ 共用 ｜ P0 ｜ 依据 R1 §1.3
- Given 用户进入"关于 / 开源许可"
  When 查看
  Then 可见：MPL-2.0 全文、Xray-core 版本与来源 URL、**Source Code 获取方式**（对应 tag 的源码地址）、第三方依赖清单（NFR-10）
- Given 产品修改了 Xray 的任何源文件（含 OHOS 补丁）
  When 发版
  Then 被修改文件必须以 MPL-2.0 公开；本要求的落实状态须在发版检查单中显式确认（不得依赖记忆）

**FR-31 协议/传输支持集合（能力声明与兼容）** ｜ 共用 ｜ P0 ｜ 依据 R1 §2.1–§2.3（GA v26.3.27，源码级判据）

**兼容性边界（两档，不可混为一谈）**：

| 档位 | 传输 | 承诺 |
|---|---|---|
| **必须支持** | `raw`(tcp)、`xhttp`、`mkcp`、**`websocket`**、**`grpc`**、`httpupgrade` | 能导入 + 能建连 + 能出网，逐项真机验收 |
| **明确不支持** | `quic`、`h2`、`h3`、`http` | 上游 GA 已移除，配置加载即报错（`PrintRemovedFeatureError`）；**不得承诺兼容**，导入时给出明确提示 |

- MVP 协议：**VLESS（含 XTLS-Vision flow）**、**VMess**、**Trojan**、**Shadowsocks（含 SS2022 方法族）**；安全层 **REALITY**（仅允许 `raw` / `xhttp` / `grpc` 三种承载，源码显式校验）
- `websocket` / `grpc` / `httpupgrade` 虽被上游标记 **deprecated**，**仍完整支持**（机场节点以 ws/grpc 为主，不能因标记 deprecated 而剔除）；仅在保存时提示"上游建议迁移至 XHTTP"，**不阻断使用、不降级承诺**
- 明确不作为 MVP 依赖：`masque` / `xdrive`（仅上游预发布 HEAD 存在）
- Given 用户导入含 `quic`/`h2`/`h3` 传输的节点
  When 保存或连接
  Then 明确提示"该传输已被当前内核版本移除，无法连接"，并建议改用 XHTTP/WS/GRPC
- Given 验收测试
  When 逐项执行
  Then 六个"必须支持"传输各有一条真机建连用例；`REALITY × (raw/xhttp/grpc)` 三种组合各一条；REALITY 与 ws/mkcp 的非法组合必须被前置拦截（不得交由内核报错）

### 4.10 后续期次需求（FR-25 ~ FR-28 / FR-32 ~ FR-34）

> 注（Z1 核对）：FR-07（自定义路由规则编辑）虽属 V1 期次，但其需求正文在 §4.4、设计落点见 `design.md` §5.2（D-11/D-13），**不在本节**；本节仅收录未在别处展开的后续期次条目。

- **FR-25 流量与连接统计**（共用，P1）：显示本次会话与累计上下行字节、活跃连接数；数据来源为内核统计接口（R1 §4.1）。验收：与系统流量对比误差 ≤5%（口径待 P-24 回填）。
- **FR-26 订阅更新**（共用，P1）：支持手动更新与可配置频率（默认仅手动，自动更新需用户显式开启）；更新失败保留旧节点并提示。
- **FR-27 桌面卡片/快捷方式启动**（共用，P1）：从桌面卡片一键"启动并连接上次节点"；平台不支持开机自启（§2.1 B-3）。
- **FR-28 停用/重置/清除数据**（共用，P1）：提供"仅停用代理"与"清除全部配置"两级操作；后者需二次确认并说明不可恢复。
- **FR-32 应用内局部代理模式（形态 B）**（B，P2/V1）：`127.0.0.1` 本地 SOCKS/HTTP 入站 + 手动配置引导。
  - 定位：**不是 A 的降级替代**，而是「低侵入/可共存」模式——不需 VPN 信任授权、不接管全局流量、不占系统唯一 VPN 槽位、不触发 2203002；
  - 覆盖范围（必须显式告知）：仅本应用、内置 WebView，以及自愿接入 `@ohos.net.http` 且设置 `usingProxy=true` 的应用（R2 §3.4/§9.5）；
  - 平台约束须明示：应用退后台后 Socket 可能断开（R2 §3.4 B-1），存活能力不优于形态 A。
- **FR-33 多语言**（共用，P1）：简体中文 + English；切换语言无需重启。
- **FR-34 无障碍基础能力**（共用，P1）：关键状态（已连接/未连接/受保护范围）可被读屏朗读；主要操作可键盘/焦点导航完成；对比度满足 WCAG AA。

### 4.11 由竞品痛点反推出的需求（FR-35 ~ FR-38）

**FR-35 本地入站端口安全** ｜ 共用 ｜ P0 ｜ 依据 R3 §9 K6、§7.1 #5457（347 评论，最高热 issue）
- 背景：中继架构（tun2tsocks → 本地 SOCKS → 内核出站）**必然**在本机开一个入站端口，等于对同机任意应用开放代理能力。
- **分支说明**：若最终采用「内核与 tun2socks 同进程」的实现（D1 的 A1 路线），该端口**不存在**，本条自动失效；采用跨进程 loopback（A3）时本条完整生效。为避免"验证时找不到该端口"的困惑，验收前须先确认实现路线。
- Given 隧道建立
  When 本地入站启动
  Then ① **默认仅监听 `127.0.0.1`**（禁止默认监听 `0.0.0.0`，此项比端口号重要）；② **默认开启鉴权**（SOCKS user/pass 或等价一次性 token），可关闭，关闭时 UI 明确提示"本机其他应用可能使用该代理通道"；③ 端口随机分配并记录到诊断页。
- **端口随机化的定性**：仅用于**降低端口碰撞/误连**，**不视为安全措施**——本机应用可扫描枚举端口。
- **负向验收**：a) 另一应用连接 `127.0.0.1:<port>` 且未提供凭据 → 必须被拒绝；b) 抓包确认监听地址仅为回环（`0.0.0.0` 监听即判不通过）；c) 关闭鉴权时，首次连接必须有可见风险提示。

**FR-36 数据面健康探测与自愈** ｜ A ｜ **P0** ｜ 依据 R3 §9 K8、§7.1 #5057；leader 裁决
- **定位**：不是可延后的增强项，而是 FR-13/FR-14/FR-15 三条红线的**实现前提**，且 K1 的 `B-07` 门禁把"看门狗"列为出口条件——故必须在 MVP。
- 最小范围（**不含"全自动恢复"这种野心**）：
  1. **健康探测**：内核存活（进程内状态机）+ 数据面可用性（周期性对既定目标做轻量连通探测，间隔与超时按功耗约束设定）；
  2. **自愈动作**（按序尝试，最多 2 次）：重启内核 → 停止隧道 → 上报"需用户介入"；
  3. **用户可见状态**：探测过程中 UI 显示"连接检查中/已连接但无流量"（与 FR-15 同状态集），止损动作完成后必须刷新为真实状态。
- Given 隧道显示"已连接"但数据面失效（tun2socks 侧静默死亡）
  When 探测命中连续 2 次失败
  Then ≤N 秒内（FR-13 的 N 口径）转为"已连接但无流量"，自动执行一次重启内核；仍失败则停止隧道并提示，**不得**继续以"已连接"示人
- Given 引擎实现
  When 设计评审
  Then 需求侧要求"引擎**可替换**"这一能力存在（实现层至少支持一种可切换的 tun2socks 实现），具体方案由 D1 决定

**FR-37 规则命中可解释** ｜ A ｜ P1 ｜ 依据 R3 §8.3
- Given 用户开启"规则命中记录"（默认关闭，仅保留最近 N 条）
  When 发生一次连接
  Then 可查看该连接的「命中规则 / 最终出站（代理/直连/拦截）/ 是否经嗅探还原域名」
- 隐私约束：默认关闭、仅本地、不记录完整 URL、可一键清空

**FR-38 高级字段编辑的三层能力** ｜ 共用 ｜ P1 ｜ 依据 R3 §8.2；leader 裁决（与 D-09「内核配置是生成物、不作可编辑真源」对齐）
- **原表述作废**：「整份 JSON 与 UI 双向一致」不再作为需求——生成物一旦可回写就有两个真源，配置迁移、订阅更新、内核升级会互相打架。
- 三层能力（边界清晰，不得混用）：

| 层级 | 能力 | 说明 |
|---|---|---|
| ① **白名单高级字段可编辑** | `mtu`、`mux`、`fingerprint`、部分 `sockopt`、`sniffing` 策略 | **进域模型，是正经真源**，可编辑、可迁移、可校验 |
| ② **生成结果只读查看 / 复制（脱敏）** | 供排障自查 | **禁止回写** |
| ③ **整份 JSON 仅"导入转换"** | 解析 → 映射到域模型 | 不认识的字段**明确列出并拒绝导入**，不得静默丢弃 |

- Given 用户在白名单字段中修改 `mtu` 或 `mux`
  When 保存
  Then 值进入域模型并参与下次配置生成；越界时前置拦截并给出合法范围
- Given 用户导入一份完整 JSON
  When 解析
  Then 能映射的字段进入域模型；**不能映射的字段逐条列出**并让用户选择"忽略并继续 / 放弃导入"；**不得**静默丢弃字段
- Given 用户查看生成的配置
  When 复制
  Then 内容脱敏（不含 UUID/密码/私钥），且界面明示"只读，修改请用高级字段或导入转换"

### 4.12 接管面变更的交互约束（FR-39）

**FR-39 接管面配置变更必须断连并提前告知** ｜ A ｜ P0 ｜ 依据 R3 §9 K12（VPN 路由只能一次性下发，无增量接口）；leader 裁决

| 类别 | 字段 | 变更后果 |
|---|---|---|
| **接管面**（触发断连重建） | `routes`、接管网段、LAN 绕过、`isIPv6Accepted`、**分应用名单 `trustedApplications`/`blockedApplications`** | **当前连接会断开**，需重建 VPN 连接 |
| **内核层**（不断连） | 分流规则、DNS 策略、切换节点（快速重启内核、不重建 VPN） | 无需断开隧道 |

- Given 用户修改任一**接管面**字段（**包括只是勾选/取消一个分应用**）
  When 点击保存
  Then 弹二次确认并明示"该设置变更将**断开当前连接并重建**，期间网络会短暂中断"；确认后执行断连重建，UI 显示"重连中"
- Given 用户修改**内核层**字段
  When 点击保存
  Then 提示"该设置无需断开连接"，不触发断连确认
- **负向验收**：勾选一个分应用后若未出现断连确认提示，或断连后 UI 未呈现重建过程，判不通过
- 文案要求：必须解释原因（"系统 VPN 路由不可增量更新"），避免用户当成缺陷

| 稳态内存 RSS（空闲/传输中） | 指标待回填 | 由 **P-02/P-24** 回填 |
| 吞吐（TCP/UDP 各一组） | 指标待回填 | 由 **P-24** 回填 |
- **禁止表述**：不得出现"业界常见十几 MB""通常几十毫秒"等未经测量的量级描述；发布材料同样受此约束。
- 验收方法：真机 + 同机同批用例（与 P-01/P-21 基线一致），每组 ≥20 次取 P50/P95/max。

### 5.2 功耗（NFR-02）

- 三态基线：空闲已连接 / 持续传输 / 后台保活，各测 30 分钟，指标待回填（**P-24**）。
- 约束（非数值）：轮询仅用于低版本兜底；**前台 ≤5s、后台 15~30s**，且仅在"隧道应为活动"时进行，隧道未激活立即停止；省电模式下的周期拉长必须被记录并在 UI 反映"状态最后确认时间"。

### 5.3 稳定性（NFR-03 / 04 / 05 / 13，互不替代）

**NFR-03 崩溃率**
- 指标：核心场景（连接建立、节点切换、长时间传输、网络切换）每千次会话崩溃 **≤1 次为目标值、≤3 次为红线值（超红线阻断发布）**。两值均为**本项目设定的目标，非行业实测基线**。
- 会话定义：一次「建立连接 → 断开或被终止」计 1 次；单会话超过 4h 按 4h 切片计数（避免长驻会话稀释分母）。
- **隔离边界（重要，勿写成"无隔离"）**：手机端**不能创建子进程**，内核以 `.so` 同进程加载；但内核运行的 `VpnExtensionAbility` 与 UI 主进程（`UIAbility`）**是两个进程**——扩展进程崩溃 ⇒ 隧道断、UI 主进程可感知并重连（FR-13/FR-14/FR-16）；**扩展进程内部**的 Xray 内核与 tun2socks 之间**没有隔离**，一方崩溃会带走整个扩展进程。故：**「主进程 ↔ 扩展进程」有隔离；「内核 ↔ 数据面引擎」无隔离**。
- **校准纪律**：初始值为未实测设定；`J-01` 通过后（P-15 受控 panic 存活验证 + 真实传输压测结论出具）**强制校准一次**，须附「实测数据 + 差距说明 + 决策（减功能/接受风险/调门槛）」。此后任何门槛调整必须留痕：「时间 | 原值→新值 | 原因 | 数据依据 | 决策人」，缺项视为无效变更；**发布前静默放宽一律不接受**。

**NFR-04 恢复成功率**
- 主指标 ≥99%（初值，由 J-01 后校准）。
- 分子：用户在「配置存在但隧道未建立」状态下触发恢复，且 ≤ 实测基线内达到「隧道可用且 UI 状态一致」的样本。
- 分母分四类、分别统计：**S1 用户主动杀进程/主动断开**（单列参考，不拉低主指标）、**S2 系统回收或息屏冻结**、**S3 应用崩溃**、**S4 网络切换**；主指标分母 = S2+S3+S4。
- 不计入分母、单列「不可恢复」：用户删除配置、节点被订阅移除、凭据失效。
- 失败必须可归因到错误分类（网络不可用/节点不可达/2203002 冲突/权限未授予/配置无效），否则记「归因缺失」并单独暴露。

**NFR-13 崩溃可诊断（与 NFR-03 并列，互不替代）**
- 指标：崩溃后**下次启动 ≤3s 内**呈现「上次异常退出」（时间、场景、最后一步操作、崩溃栈摘要），并提供诊断包导出入口；诊断包至少含：日志尾部、配置快照（脱敏）、设备型号与系统版本、内核版本、崩溃类型。
- 因「内核与应用同进程、无隔离兜底」，本项为**必选**而非可选优化。
- 验收方法：注入受控崩溃（P-15）→ 冷启动计时 → 检查呈现内容与诊断包字段完整性；**诊断包内不得含凭据**（与 NFR-06 联动）。
- 依据：leader 裁定；R2 §4.3、§7 #23；R1 §2.4.3 P8。

**NFR-05 长跑与退化**
- 连续运行 8 小时（含锁屏、网络切换）不得出现"需要用户手动重启应用才能恢复"的状态；CPU 占用不得单调上升（依据 R3 §7.1 #4641 长跑退化）。阈值待 **P-24** 回填。

### 5.4 安全（NFR-06）

| 要求 | 验收 |
|---|---|
| 凭据（UUID/密码/订阅 token/私钥）落盘加密 | 存于 ASSET（`@ohos.security.asset`，单条 ≤1KB，TEE 内加解密）；数据库文件不得明文包含凭据（可用外部工具抽查失败为证） |
| 加密密钥 | 由 HUKS 生成与保管，明文密钥不出安全环境 |
| 节点库/订阅/规则 | `relationalStore` + `StoreConfig.encrypt=true`（创建时确定，不可后改） |
| 日志脱敏 | 日志与导出包中不得出现订阅 URL、UUID、密码、私钥全文；验收用正则扫描导出包 |
| 本地入站端口 | 见 FR-35（回环绑定 + 随机端口 + 可选鉴权） |
| 更新通道 | 见 FR-30（签名 + 防回滚 + fail-closed） |
| 冷启动环境变量 | 传给内核的环境变量必须在**首次 dlopen 之前**设置；运行期禁止 `setenv`（依据 R3 §9 K2，实现红线，需求侧只要求"配置项须在启动前确定"） |

### 5.5 隐私（NFR-07）

- **MVP 不上传任何数据**：无遥测、无崩溃自动上报；诊断包仅本地生成、由用户手动分享。
- 不内置任何服务器/订阅源/节点分享（合规红线，依据 R3 §8.6）。
- 诊断与日志默认仅本地保存；提供"一键清空日志/诊断"入口。
- IPv6 默认策略：接管并阻断（不产生 v6 出网），不构成默认泄漏面（NFR-11 F-1）。
- 权限最小化：仅申请 `INTERNET`、`KEEP_BACKGROUND_RUNNING`、`GET_NETWORK_INFO`（如需 Wi-Fi 信息再加 `GET_WIFI_INFO`）；每项在隐私说明中给出用途。

### 5.6 可用性（NFR-08）

- 多语言：简体中文 + English（FR-33）；切换不重启。
- 无障碍：关键状态可读屏朗读、主要操作可焦点导航、对比度 ΔE 满足 WCAG AA（FR-34）。
- 错误文案准则：**默认给结论（可行动），原始错误可展开**；禁止把内核错误码原样直出作为唯一信息（依据 R3 §7.1 #268/#1499）。

### 5.7 合规（NFR-09）

- **MPL-2.0 四层义务**（依据 R1 §1.3，需求侧照写）：
  1. 分发时保留 MPL-2.0 全文与版权声明；
  2. 不修改源码、以独立 `.so` 分发 → 提供上游对应版本（XTLS/Xray-core tag）**Source Code 获取方式**；
  3. 一旦修改任一源文件（含 OHOS 补丁）→ **该文件以 MPL-2.0 公开**，其余文件不受影响；
  4. **外层 MIT 包装（libXray）不能免除内层 MPL 义务**；libXray 自身 MIT 声明须保留。
- 发版检查单必须含"MPL 义务确认"一项（不得依赖记忆）。
- 分发与资质：见 §7（三条路线与省内/跨省许可差异），产品不得在无相应资质时选择"公开发行"。
- 商标：应用名称不得暗示 Xray 官方背书（R1 §1.3【待验证】项）。

### 5.8 兼容性（NFR-10）

- `compatibleSdkVersion = 12`（HarmonyOS NEXT 5.0.0 起）；`targetSdkVersion` 跟随最新 Release。
- 能力差异必须按 **API 档位**处理并可见：分应用上限 **64（API 12~22）/ 256（API 23+）**；`BEARER_VPN` 事件通道 **API 12+**；`createVpnObserver`/`onAuthorizationResult` **API 26.0.0 起，最低兼容版本不得依赖它**；多 VPN（`generateVpnId`）**API 20+** 且不作为需求前提。
- 宣传约束：MVP 支持期对外只提 64，不以 256 作卖点（避免宣传与 API 12 设备能力不符）。

### 5.9 fail-closed（NFR-11，定义见 §2.2）

- 验收：F-1~F-5 五项各一条用例；其中 F-1（IPv6）必须用**分协议出口 IP 归属**判定（v4/v6 各打一次），且 `aa force-stop` 冷启动后再验。
- 已知违背面：B-1（进程终止 → 恢复直连），由 FR-17 明示，**不视为本原则失败**。

### 5.10 可维护性（NFR-12）

- 关键第三方依赖须在文档显式登记六字段：**名称 / 版本 / 上游活跃度 / 停更影响 / 替代路线 / 锁版本方式（commit hash 或 tag + 校验和）**；清单变动须留痕。
- 已知必列项：OHOS Go fork（`star4277/ohos-go`，个人 beta 版）、libXray、tun2socks 实现、Xray-core（钉 GA `v26.3.27`，**不得跟随 latest —— latest 常为 prerelease**）。

## 10. 被否方案与理由（保留线索，不删除）

| # | 被否方案 | 否决理由 | 依据 |
|---|---|---|---|
| X-1 | 形态 B 作为形态 A 的"降级替代" | B 的后台存活能力**不优于** A（同样只能靠长时任务），且多一条"退后台 Socket 可能断开"的官方风险；B 的真实价值是低侵入/可共存 | R2 §3.4；leader 裁定 |
| X-2 | 「A 红灯 → 收缩为 ArkWeb 容器内转发」 | 若收缩后未覆盖流量直连，即属 **fail-open**，违反 NFR-11；属**有条件的否决**：V1 之后若要恢复该方向，必须先解决未覆盖流量的阻断（如断网式容器），且不得作为 MVP 讨论项 | leader 裁定 |
| X-3 | 开机自启 | 平台不支持（仅系统应用 + 需设备预置授权） | R2 §4.4 |
| X-4 | 把「tun fd 直连内核」作为 MVP 路线 | **未验证的替代路径**（Android `AndroidLibXrayLite` 有先例；Hey 为双内核共用数据面主动绕开），MVP 验证目标定为 tun2socks 路径 | R3 §3.3；R1 §5.4 |
| X-5 | WS/gRPC 作为长期主线传输 | 上游已标记 deprecated，主线为 XHTTP；但 **必须保持兼容**（机场节点以 ws/grpc 为主） | R1 §2.2 |
| X-6 | 节点热切换（零中断） | 控制面无整体 reload、无原子换节点原语，无连接迁移 | R1 §4.2 |
| X-7 | 固定本地入站端口（如 10808/18082） | 同机任意应用可白嫖代理；随机端口 + 回环绑定 + 可选鉴权 | R3 §9 K6 |
| X-8 | 以"不接管 v6"作为关闭 IPv6 的方式 | "不接管"≠"不泄漏"；正确做法是接管 + 内核侧 `block ::/0` | R3 §9 K11 |
| X-9 | 内置节点/订阅源/节点分享 | 合规红线，且负向差异化更有利 | R3 §8.6 |
| X-10 | 复制 Hey 的 `.ets` 代码 | Hey 为 GPL-3.0（传染）；只借鉴思路与架构结论 | R3 §1.3、§8.6 |
| X-11 | 「首个/首款 HarmonyOS Xray 客户端」定位 | 已有先于本项目的实现（Hey 被 Xray 官方 README 收录） | R3 §0 |
| X-12 | 承诺在线率作为可用性指标 | 平台进程被杀即断连，承诺在线率是自欺；改承诺"恢复成功率" | leader 裁定 |

### 12.3 结论演进表（新结论不擦除旧结论）

| 早期结论（含 Interim 快照） | 现行结论 | 取代原因 |
|---|---|---|
| 「手机端不能起子进程 ⇒ 内核崩溃 = 应用崩溃、无任何隔离」 | 隔离边界为**两层**：UI 主进程 ↔ VPN 扩展进程**有隔离**（扩展崩溃则隧道断、主进程可感知重连）；扩展进程内 **Xray 内核 ↔ tun2socks 无隔离**（一方崩带走整个扩展进程） | R3 §3.2（内核运行在扩展进程内）；leader 裁决 |
| 「VPN 需华为侧资质审批；审批结果不可控、可能拖 15 天」 | 系统层**零审批**，仅首次用户授权弹窗；资质只出现在"公开发行"环节（且属合规存疑） | R2 §3.1/§3.2 |
| 「默认配置下 IPv6 真实泄漏（承诺边界首条）」 | 现行设计为**接管 + 内核侧 `block ::/0` 阻断**：默认不漏、不提供 v6 出网；开启 v6 代理需用户显式选择 | R3 §9 K11；leader 裁决 |
| 「保活 best-effort、失败可接受」 | 保活是**必需机制**（必须申请长时任务），只有"稳定运行时长"不作 SLA | leader 修正 + R2 §4.2 |
| 「形态 B 是 A 的降级方案」 | B 为**低侵入/可共存模式**（V1），不构成 A 的兜底；MVP 无形态替代 | R2 §3.4；leader 裁定 |
| 「tun fd 直连内核已被证实不可行」 | **未验证的替代路径**，不在 MVP 范围（Android 有先例） | R3 §3.3 |
| 「分应用代理上限未知」 | 官方明文 **64（API 12~22）/ 256（API 23+）**，两列表互斥 | R2 §3.6 |
| 「分应用可勾选已安装应用」 | 三方**无法枚举**已安装应用，改为预置表 + 搜索 + 手输 | R2 §9.5 |
| 「已安装应用枚举能力待查」 | 结论：**④ 不可用** | R2 §9.5（P-18） |
| 「PC 清单：VPN 活跃期进程不被冻结」 | 长时任务类型表**无 vpn 类型**；保活须借用类型（语义匹配风险由 P-07 判定） | R2 §4.2 |
