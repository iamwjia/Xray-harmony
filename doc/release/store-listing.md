## 二、应用介绍（长描述，可直接粘贴）

```
Tunnelix 是一个面向 HarmonyOS NEXT 的本地代理客户端，支持 vless / vmess / trojan /
shadowsocks 四种协议，TCP / WS / gRPC / HTTP2 / mKCP 五种传输，以及 TLS / REALITY 安全层。

它把控制权交回给你：
· 节点自己填，或从分享链接、订阅地址一键导入
· 分流规则自己定：按域名、IP 决定走代理、直连还是阻断，规则顺序就是优先级
· 代理只在你要用时才开；首次连接会由系统弹窗向你本人请求授权
· 凭据存放在系统安全存储里，不落明文；日志写入时自动脱敏
· 备份是一个加密文件，口令由你设定，忘了就打不开，我们也找不回来

应用内没有账号、没有统计、没有广告，不收集你的任何数据。
开源说明与第三方组件许可在「设置 → 关于 → 开源许可」中完整列出。
```

### 卖点提炼（用于短描述 / 截图配文）

1. **四种协议一套配置** —— vless / vmess / trojan / shadowsocks，导入即用
2. **分流看得见** —— 规则按顺序生效，域名与 IP 分开填，命中后走代理/直连/阻断
3. **凭据不进明文** —— 系统安全存储（HUKS）+ 日志脱敏，备份整包加密
4. **不偷偷联网** —— 订阅更新、分流数据更新都要你亲手点

## 四、审核需要准备的口径（问答预案）

| 审核可能问 | 我们的回答（依据） |
|---|---|
| 为什么需要 VPN 能力？ | 代理客户端必须接管设备流量；通过 `type: "vpn"` 扩展实现，用户首次连接时由系统弹窗授权，应用无法静默开启 |
| 是否收集用户数据？ | 不收集。无统计/崩溃/广告 SDK，无账号体系；凭据只存本机安全存储 |
| 分流的 geoip/geosite 数据从哪来？ | v2fly 官方发布构建，仅在用户点「联网更新」时下载；许可与来源在「开源许可」页列出 |
| 是否包含开源组件？许可是什么？ | 包含 Xray-core（MPL-2.0，未修改）、libXray（MIT）、tun2socks（MIT）、gVisor（Apache-2.0）；全文见仓库 `THIRD-PARTY-NOTICES.md` |
| 是否会被用于绕过监管？ | 本应用是通用代理客户端，不内置任何节点、不提供任何服务器；节点与订阅均由用户自行添加 |
| 是否含自建服务器或收费？ | 无。应用内不含任何付费、充值、推广入口 |

## 五、需要你拍板的三件事

1. **首发版本号**：建议 `1.0.0` / `versionCode 1000000`。当前 `entry/oh-package.json5` 的 `version` 还是 `1.0.0`，
   但 `build-profile.json5` 里没有显式 `versionName/versionCode`——上架前必须补，否则市场按默认值处理。
2. **应用名称是否加后缀**：如「Tunnelix 代理」以便搜索命中，还是保持纯英文名。纯英文名在中文市场的搜索劣势要认。
3. **是否需要首启隐私政策弹窗**：见 `doc/release/privacy.md` 第四节第 2 点——这是审核常见卡点，我建议补。
