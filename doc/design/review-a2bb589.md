## 2. 关键发现：`fontChip` 成了"让脚本变绿"的通道

`FontSize.fontChip = 11`，它在本规范里是**标签档**（§3.2：仅标签类不可点短标签，≤4 字）。本轮为了让 `fontSize(数字)` 归零，有 3 处把正文/元信息换成了 `fontChip`：

| 位置 | 现状 | 应为 | 等级 |
|---|---|---|---|
| `Licenses.ets:102/107/112/117/122/127` | **7 段 MPL/商标/数据来源合规正文** → `fontChip` 11fp，**且无 `lineHeight`** | `bodySm` 13 / 20 | **P0（A-03 + A-04 双违规）** |
| `Licenses.ets:87-89` | 版本 / 用途 / 修改情况（元信息）→ `fontChip` | `caption` 12 / 16 | P1 |
| `Licenses.ets:130` | 页脚说明 → `fontChip` | `caption` 12 / 18 | P1 |
| `Logs.ets:249/254` | **日志 level / time** → `fontChip` | `caption` 12 / 16（level 还要 w600） | **P0（§5.6 明写 12/16）** |
| `DevPanel.ets:286` | 说明文字 → `fontChip` | `caption` 12 / 18 | P1 |
| `NodeRow.ets` | 分组 chip → `fontChip` | ✅ 合法（标签档） | — |

**根因不是笔误，是验收口径有洞**：`fontSize(数字) = 0` 只能证明"没有裸数字"，证明不了"用的是对的那一档"。一个能被改名绕过的机器口径，等于没有。

**已补两条机器可判口径（§11.8 第 18 项 + §3.2 警示）**：

- `fontChip` 用途白名单：标签 chip / 徽标数字；
- 每处 `FontSize.fontChip` 所在 `Text` 必须 `maxLines(1)`，标签 chip 还要 `maxWidth 60`；
- 多行正文、说明、元信息出现 `fontChip` 即违规。

## 3. 关于 P2 是否要收（你问的那条）

**结论：DevPanel 的结构不动，Licenses 不能算 P2。**

- **DevPanel**：PoC 探针页、不对外，结构不动我同意。但上面那 1 处 `fontChip` 说明文字要换成 `caption`（一行改动，不算重排）。
- **Licenses**：它不是"重排收益低于功能缺口"的问题——**它现在正文 11fp 且无行高，是 A-03/A-04 违规**（可访问性判据，不是审美）。而且这一页是 **MPL-2.0 义务的展示面**：字小到读不清，等于告知义务打折。
  **但也确实不需要全页重排**，只需 3 类最小改动（约半小时）：

  | 改什么 | 从 → 到 |
  |---|---|
  | 7 段合规正文 | `fontChip` → `bodySm` 13 / **20** |
  | 版本/用途/修改情况/页脚 | `fontChip` → `caption` 12 / 16（页脚 18） |
  | 章节标题 | `body` → `titleMd` 16 / 22 |
  | 许可证标签 chip | `fontChip` 保留，但补 `maxWidth 60` + 视觉高 28 |

  **不做的**：卡片重排、间距体系化、深色专项（那些确实是 P2，排功能之后）。
