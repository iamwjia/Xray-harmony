## 1. 需要二选一的规范冲突：`last` 的更新时机

**实现**：`SocksGuard.rotate()` 里就写入快照（`SocksGuard.ets:60-65`），而 `rotate()` 发生在 `kernel.start()` **之前**。

**规范 L-2 原文**：「只在**绑定成功**那一刻更新」。

**两者冲突，只能选一个。我裁定：采纳实现，规范改口。**

理由：绑失败时用户最需要知道的恰恰是"我这次试的是哪个端口"。若只在成功后记录，**失败场景（报障主场景）反而没有线索**，与 L-2 自己想解决的问题自相矛盾。规范 L-2 改为：

> **L-2（改口 2026-11-22）**：在**端口轮换即刻**写入快照（早于内核启动）；断开**不**置空；进程死亡自然为空。
> 代价需知：内核启动失败时，快照里会留下一个"尝试过但未监听"的端口——这对外是**特性**（有线索）不是缺陷，但文案上不可声称"当前可用"，所以 Logs 用 `KernelService.isRunning()` 区分"当前 / 最近一次"。

## 2. 你问的两处

### Q1 `lastEndpoint` 的测试只能结构级 —— **同意，规范改口**

你说得对：ArkTS 静态类抽不出可跑的等价函数体，硬写 JS 只会测副本。**§11.8 第 9 项改为「结构断言 + 手册验证」**，并明写"不是脚本可判定"：

| 断言 | 方式 |
|---|---|
| 返回副本（改返回值不影响内部） | 结构级（单测可覆盖） |
| 不落盘 / 不进日志缓冲 | 结构级（grep 无 `preferences` / 无 `Logger.push`） |
| 幂等（连调 3 次等值） | 结构级可近似（同一快照对象等值比较） |
| **连接 → 断开 → 仍可读** | **只能手册验证**（你已实测：进日志页仍显示"最近一次…（已断开）"） |

这条的原则与 §8.2（A-07 不可脚本判定）一致：**运行期行为不进脚本，进手册**。不许为了"看起来可自动化"而写一个只验证结构的假测试冒充行为验证。

### Q2 `host` 硬编码 `'127.0.0.1'` —— **接受不加参数，但必须收成单一来源**

`SocksGuard.ets:63` 写 `snap.host = '127.0.0.1'`，而 `KernelConfigBuilder.ets:35` 写 `"listen":"127.0.0.1"`——**两处字面量**，正是你担心的"两个来源"。

**定论**：不加参数（你的判断对，加参数会引入"日志地址"与"绑定地址"两个可变量）；但把 host 提成一个常量并由两处共同引用：

```
SocksGuard.LOCAL_HOST = '127.0.0.1'   // 或 platform/LocalProxy.ets 里统一
KernelConfigBuilder 的 listen 用它
SocksGuard 快照用它
Logs 显示用它（已经是读快照，自动一致）
```

**验收**：全仓 `grep "127.0.0.1"` 只剩常量定义 1 处（注释与文档除外）。这是"单一口径"的实现，不是新功能。

## 3. 字号字面量（你问要不要扫清单）

**不要清单，直接改。** 清单会多一轮，而这件事本来就是机器可判的：

- 目标：全仓 `pages/` + `components/` 的 `fontSize(数字)` 与 `lineHeight(数字)` **= 0**；`font_chip` 的 11fp 仍走 `FontSize.fontChip`，不受影响。
- 验收（我用这三条一次验完，不需要你发文件）：
  1. `grep -c "fontSize([0-9]" pages/ components/` = 0
  2. `grep -c "lineHeight([0-9]" pages/ components/` = 0
  3. 字号取值集合 ⊆ {24,20,16,15,14,13,12,11}
- 注意一个坑：`Text('\u2713')` 之类图标字形走 `IconSize.*`，**不是字号**，不要被脚本误改。
