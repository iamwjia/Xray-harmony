## 0. 文档口径

### 0.1 判定等级

| 标记 | 含义 | 处置 |
|---|---|---|
| **必须** | 可访问性 / 误触 / 信息丢失 / 深色崩溃。每条都能用一个条件判定 | 本批必改，不接受"以后再说" |
| **建议** | 视觉一致性、节奏、观感。改不改产品都能用 | 可延后 |
| **待裁决** | 触及信息架构（IA）或产品文案，超出视觉职权 | 报 team-leader 定 |

| 数据 | 来源 |
|---|---|
| 颜色 / 字号 / 间距 / 圆角 | **读源码逐行统计**，非目测 |
| `Button` / `TextInput` 默认高度 40vp | **ArkUI 默认值推断**（源码未显式设 height），标记为`【待复核】`，请在模拟器上量一次 |

### 1.2 三条结构性问题

1. **颜色是"每处写死"而不是"引用令牌"**：深色模式无法通过加一套资源实现，必须先把 128 处改成 `$r('app.color.*')`。
2. **文字最小到 10fp**：10fp 在 360vp 宽屏上单字约 10vp 宽，是"能看见但读不快"的临界；日志正文、状态调试串、说明文字大量落在 10/11fp。
3. **触控目标未定义**：全仓无一处显式 `height(44)`；图标型/文字型点击区（`Text('↑')`、`Text('删除')`、`Button('+')` 36×36）命中区等于字形边界。

## 2. 三个已知问题的正面回答（结论先行）

### 2.1 节点列表一行 5 个点击区

**现状数值**：一行内 6 个子元素（文字列 + `↑` `↓` `选择` `编辑` `删除`），`Row({space:8})`，5 个间隙共 40vp。

- 命中区实测推算：`↑`/`↓` 为 `fontSize(14)` 的 `Text`，无 `padding`、无 `height` → 命中区 ≈ **14×16vp**；`选择`/`编辑`/`删除` 为 12fp 两字 → **24×17vp**。**全部低于 44×44vp，5/5 必须改。**
- 文字列被挤压：360vp 屏 − 页面 padding 32 − 行 padding 24 = 304vp 内容宽；减去 5 个间隙 40 + 5 个操作区约 112 → **文字列只剩约 152vp**。元信息行 `vmess · sub.example.com:44321` 在 11fp 下约需 190vp ⇒ 必然省略或压字。
- 更糟的是**命中区重叠**：整行 `Row` 有 `onClick`（选中），4 个文字按钮叠在上面。手指落在 `删除` 边缘 3vp 之外，结果是"选中了"而不是"删了"——错误方向还算安全；但落在 `编辑` 与行之间，就是"想编辑却只是选中"的静默失败。

**方案**：一行只保留 **2 个命中区**。

| 命中区 | 尺寸 | 行为 |
|---|---|---|
| 整行 | ≥ 64vp 高 × 全宽 | 选中该节点（主操作，正好是最高频动作） |
| 溢出按钮 | 44×44vp，右侧 | 打开 `Menu`：编辑 / 上移 / 下移 / 删除（删除红字） |

**为什么可以隐藏 ↑↓ 和删除/编辑**（信息密度硬约束下必须说清）：

- `↑`/`↓`：用户只在"把常用节点排到前面"时用一次，之后长期不动；一次操作藏在菜单里代价极小。而 `协议 · 地址:端口 · 分组 · 选中态` 四要素是**每次扫读都要看**的，**永不隐藏**。
- `编辑`：低频（导入后基本不改），且整行菜单零距离可达。
- `删除`：破坏性操作，放进菜单反而**降低误触**（现在它是唯一一个紧贴其他按钮的红色文字）。
- 收益：文字列从 **152vp → 222vp**（精确核算见 §11.4：316 − 12 指示 − 34 形态 − 48 溢出；本节此前按 24 指示位估的下界 218 以 §11.4 为准），元信息不再截断。

### 2.2 编辑表单 18 个控件 + 键盘

**现状数值**（逐行数）：`TextInput` **13 个**、`Select` **1 个**、选项按钮组 **3 组（4+5+3 = 12 个 Button）**，合计 **18 个可交互控件**；每个 `Column({space:10})`，label `fontSize(12)` + 输入框（40vp 默认），单字段纵向 ≈ 17 + 40 + 10 = **67vp** ⇒ 总高约 **1206vp**，在 360×780 设备上约 **1.9 屏**。

问题不是"字段多"，是**无关字段也在要用户读**：选 `vless + TCP + 无` 的用户，仍然要滚过 WS 路径、WS Host、gRPC 服务名、REALITY 公钥、shortId、fingerprint、flow 共 7 个对他无效的字段。

**方案 A（必须）：按协议/传输/安全条件显隐**（不是折叠，是"不适用即不显示"）。

| 字段 | 显示条件 | 说明 |
|---|---|---|
| WS 路径 / WS Host | `transport == WS` | 非 WS 时这两个值恒为无效 |
| gRPC 服务名 | `transport == gRPC` | |
| SNI / serverName | `security ∈ {TLS, REALITY}` | REALITY 必填 |
| flow | `protocol == vless` | |
| publicKey / shortId | `security == REALITY` | REALITY 缺 pbk 必然握手失败 |
| fingerprint | `security ∈ {TLS, REALITY}` | |
| HTTP2 选项 | **从 `transports` 数组移除** | 内核已移除 HTTP 传输，`validate()` 会拦，但**让用户先选再被拒**是错误设计（见 §10 待裁决 3） |

典型节点（vless + TCP + 无安全）可见控件：**18 → 10**，纵向 **≈1206vp → ≈976vp**（−25%）。

**方案 B（必须）：把"保存"从"页面底部按钮"改成"吸底操作条"。**

| 项 | 数值 |
|---|---|
| 操作条高度 | 56vp（按钮 44 + 上下 6） |
| 操作条背景 | `bg_surface` + 顶部 1vp `border_subtle` |
| 按钮尺寸 | 全宽 × 44vp，圆角 22 |
| `Scroll` 内容底部 padding | **68vp**（= 56 + 12），保证最后一个字段不被操作条压住 |
| 输入框高度 | **44vp**（非 40），字号 14fp |
| label 与输入框间距 | 4vp；字段之间 16vp；Section 之间 24vp |

键盘规避：`Scroll` 已存在，字段高 44 + label 16 ⇒ 一个字段占 64vp；键盘占约 300vp 时仍可见 **4 个以上字段**，配合系统默认上移即可用。**不要**把 `Scroll` 换成 `List`（会让 `TextInput` 失焦回收）。已在 `$$`/`onChange` 双绑的写法保持不变——注释里那条"@Builder 传回调导致状态不更新"的坑不要引入。

**方案 C（必须）：错误就近显示。** 现状只有表单最底部一条 12fp 红字（`saveMsg`），用户点了保存后要往上找是哪个字段错。规范：

- 对应输入框下方 **0–4vp** 处显示错误文案（12fp `text_danger`），并给该输入框 **1.5vp `border_danger` 描边**；
- 底部保留一行汇总（13fp `text_danger`）用于读屏播报；
- 判定条件：「任一 `validate()` 返回非空 ⇒ 该字段必须有描边 + 文字错误」。

### 2.3 节点列表视觉重心错位

**现状**：节点名 15fp（选中时 Bold，`#1A1A1A` 级深色，对比 ≈17:1）；`选择`/`已选中` 12fp 但用 `#1976D2` 高饱和蓝 / `#2E7D32` 绿，且选中行整行铺 `#E8F5E9` 淡绿底。

视觉权重 = 字号 × 对比 × 饱和度。12fp 的高饱和色在 15fp 灰黑字旁边**必然先被看到**——用户扫读顺序变成"操作 → 内容"，与任务相反。

**方案（必须，三重编码）**：

| 编码维度 | 选中 | 未选中 |
|---|---|---|
| 位置 | 行左 3vp 宽 `accent` 竖条（通栏高 40vp，垂直居中） | 无竖条 |
| 图形 | 24vp `checkmark` 图标（`accent`） | 24vp 空心圆 1.5vp `border_strong` |
| 字重 | 节点名 15fp **w600** | 15fp **w400** |
| 底色 | `selected_row_bg`（**浅蓝** `#EAF1FE`，不是绿） | `bg_surface` |

三个理由：

1. **删掉"已选中/选择"文字**：它占 36vp 宽却不提供新信息（位置+图形已经说了），是纯噪声。
2. **绿色改蓝色**：绿色在本应用里已经是"连接成功"的语义（`status_connected`）。用绿色表示"选中"会让首页 hero 的绿和列表的绿互相稀释。**选中 = accent，成功 = success，两套语义不许混用。**
3. **灰度可辨**：竖条/图形/字重三者在去掉颜色后仍能区分 ⇒ 色盲用户可用；底色只是辅助。

**可判定条件**：「同一列表行内，`accent` 色出现次数 ≤ 1（仅选中指示）；`success` 色不得出现在节点列表」。

### 3.2 字号与行高（8 档，只许这 8 个数）

| 令牌 | size / lineHeight | 字重 | 用途 | 替换掉的现状 |
|---|---|---|---|---|
| `display` | 24 / 32 | 600 | 首页连接状态大字 | 22 |
| `title-lg` | 20 / 28 | 600 | 所有页面标题 | 18 |
| `title-md` | 16 / 22 | 600 | Section 标题（设置分组、许可章节） | 14 / 13 Medium |
| `body-lg` | 15 / 22 | 400 / 600 | 节点名、规则 pattern | 15 / 14 |
| `body` | 14 / 20 | 400 | 正文、设置项、输入框内文 | 13 / 12 |
| `body-sm` | 13 / 20 | 400 | 说明、提示、按钮文字、**可点筛选 chip** | 12 / 11 |
| `caption` | 12 / 16 | 400 | 元信息（协议·地址:端口）、时间戳、计数 | 11 / 10 |
| **`font_chip`** | **11 / 16** | **500** | **标签类**：节点行的分组 chip、许可页的许可证 chip（**不可点击的短标签**，≤4 字） | 10 |

**硬规则（必须）**：

- **禁止 `fontSize(10)`**：现状 10fp 全部上移到 `caption`(12)。
- **`fontSize(11)` 只允许一种用途：`font_chip`**（标签类短标签）。它**是一个档位，不是一个例外**——不是"某处可以破例"，而是"标签必须用这一档"。任何正文、说明、元信息、按钮文字使用 11fp 即违规。
- **区分两种 chip，不许混**：
  - **标签 chip**（`font_chip` 11/16，**不可点击**）：节点行的分组标签、许可页许可证标签。视觉高 ≥28vp；行内命中区由整行（≥64）承担，不单独设点击区。
  - **筛选 chip**（`body-sm` 13/20，**可点击**）：分组筛选、日志级别、分流模式。命中区 **44×44**，圆角 999。
  - 若标签 chip 需要独立可点（如点击按分组筛选），下沉为筛选 chip 规格：外层 44 容器 + 内层 28 视觉，**反过来（视觉 44 / 命中 28）不允许**。
- **禁止出现 8 档以外的字号**；需要更强调就用字重（600）而不是加字号。
- **⚠ 机器归零 ≠ 语义达标（2026-11-22 实测教训）**：把 `fontSize(10)`/`11` 全换成 `FontSize.fontChip` 也能让"字面量 = 0"的脚本全绿，但 `fontChip` 是**标签档**，正文用它就是违规。`fontChip` 的用途白名单只有两种：① 标签 chip（分组/许可证标签）；② 徽标内数字。**任何多行、正文、元信息 Text 使用 `fontChip` 即违规**。判定见 §11.8 第 18 项。
- **行高与字号的关系**：`lineHeight ≥ 1.4 × fontSize` 是正文默认；`< 1.4×` 只允许用于**单行标题 / 标签**（`title-md` 16/22 = 1.38、`font_chip` 11/16 = 1.45 均合规）。**多行正文低于 1.4× 即违规**。
- **每一处 `fontSize` 必须显式配 `lineHeight`**（对应表里的值）。这是"零处 lineHeight"的正面修正。
- **"可换行"= 未设 `maxLines` 或 `maxLines > 1`**：这类 `Text` 必须显式 `lineHeight`。**不写 `maxLines` 才是默认多行**，所以"只在 maxLines≠1 的地方查"会漏掉最常见的一类——这是 A-04 的机器可执行化口径（§11.8 第 19 项）。
- 可换行文本必须 `maxLines` + `textOverflow({overflow: TextOverflow.Ellipsis})`，禁止依赖默认裁切。

### 3.3 间距 / 圆角 / 描边 / 高度

| 令牌 | 值 | 用途 |
|---|---|---|
| `space-line` | **2** | **仅用于"两行文字之间的行距"**（节点行：名称行 ↔ 元信息行）。不得当作控件间距用——它和 `space-1` 语义不同，混用会让行距规则失效 |
| `space-1` | 4 | label 与输入框、chip 与文字 |
| `space-2` | 8 | 行内元素间距 |
| `space-3` | 12 | 卡片内边距、列表行垂直 padding |
| `space-4` | 16 | 页面左右边距、字段之间 |
| `space-5` | 20 | 卡片内边距（大卡，如首页 hero） |
| `space-6` | 24 | Section 之间 |
| `space-7` | 32 | 页面顶部到首块内容（无 Header 时） |

- **判定条件（必须）**：控件间距/内边距的数值 **不属于 `{4, 8, 12, 16, 20, 24, 32}`** 即需改（现有 `6`、`10`、`14` 全部落在这一条上）。`space-line=2` 是**唯一例外**，且只能出现在 `Column({space})` 的两行文字之间。

| 圆角 | 值 | 用途 |
|---|---|---|
| `radius-chip` | 4 | 分组/许可标签 |
| `radius-card` | 8 | 次级面板、日志行 |
| `radius-row` | 12 | 列表行、卡片 |
| `radius-hero` | 16 | 首页状态卡 |
| `radius-pill` | 999 | 按钮、chip 筛选 |

| 高度 | 值 | 用途 |
|---|---|---|
| `h-touch-min` | **44** | 所有可点击元素下限 |
| `h-button` | 44 | 标准按钮（胶囊，radius 22） |
| `h-button-primary` | 48 | 主操作（连接/断开/保存） |
| `h-input` | 44 | 所有 `TextInput` |
| `h-row-min` | 64 | 节点行 / 规则行（两行文本） |
| `h-chip-label` | **28** | 标签 chip 的视觉高度下限（`font_chip` 11fp + 上下 padding 2–6；**低于 28 会薄成一条线**） |

**描边**：卡片/行用 `1vp border_subtle`（**不用阴影**，深色下阴影不可见且引入视觉噪声）；输入框 `1.5vp border_strong`；聚焦 `2vp focus_ring`。

## 4. 组件规范

### 4.1 `PageHeader`（页面顶栏，8 个页面统一）

```
┌──────────────────────────────────────────────────────┐ 高 56
│ [←]     页面标题 20/28 w600              [计数|操作] │
│ 44×44    左对齐，距返回按钮 4vp          ≤2 个 44×44  │
└──────────────────────────────────────────────────────┘
```
- 返回：`44×44` 命中区，图标 20vp，**不再用 `Button('返回')` 文字按钮**（现状 12fp 文字按钮宽约 60vp、高 40vp，既占位又不达标）。
- 标题左对齐（现状 `layoutWeight(1)` 后紧跟计数，标题实际是"左对齐+两端撑开"，改成"标题固定、计数右对齐"）。
- 页面内容区左右 padding `16vp`；顶栏与首块内容间距 `12vp`。
- **顶栏内边距（2026-11-22 改口，采纳实现）**：`padding {left:4, right:8}`。理由：44vp 返回键自身已提供 22vp 视觉留白，再加 16 会把图标推到 38，明显偏内；**标题左起点 = 48vp**（4 + 44）。这条以 `PageHeader` 组件为准，五个页面不许各写一遍。
- **计数文本由页面传入（不是传数字）**：`countText: string`，如 `5 个` / `127 条` / `已启用 3 条`。单位与前缀是页面语义，组件只负责排版——`PageHeader` 内**不得出现"个/条/项"字面量**。
- **内容超一屏必须可滚**：页面根不得用固定 `Column` 把底部裁掉（`Settings` 曾因缺 `Scroll` 导致「开发者选项」入口存在但点不到）。判定：**最长状态下能滚到最后一个可操作元素**。

### 4.2 `Banner`（横幅，3 变体）

| 变体 | 底色 | 文字色 | 用途 |
|---|---|---|---|
| warning | `warning_subtle` | `warning` | 配置读取异常、geo 未就绪、设置写盘失败 |
| danger | `danger_subtle` | `danger` | 凭据迁移失败 |
| info | `accent_subtle` | `accent` | 订阅结果、操作成功提示（非阻塞） |

- 尺寸：`padding 12`，圆角 8，文字 `body-sm`(13/20)，`maxLines 3`。
- **必须**：横幅出现时**不改变下方内容的纵向位置**（现状 `if` 插入会整体下推，用户正在看的内容会跳）；做法：横幅固定插在 header 与首块之间，接受下推，但**不叠加动画**，避免"连接失败时界面跳动"。
- **必须**：横幅文本包含"怎么办"，不能只有"哪里错了"（例如凭据迁移失败要带"请重新导入该节点"）。

### 4.4 `NodeRow`（节点行，核心组件）

> **以 §11.4 为准**：那里是逐属性清单 + 精确宽度核算（文字列 222vp）与两个命中区的边界处理。本节给设计意图，§11.4 给施工值。

```
┌───────────────────────────────────────────────────────┐  高 ≥64
│ ▌ ✓    香港 01                              44×44    │  ← 名称 15/22 独占 222vp
│ 3      vless · hk01.exam…:443                    ②   │  ← 元信息 12/16
│        ①      ④                ④          ③    [⋯]  │
└───────────────────────────────────────────────────────┘
   ① 协议短名（vless/vmess/trojan/ss），固定不截断
   ② **分组 chip 在元信息行右侧**（leader 2026-11-22 裁决：从名称行移出）
      `font_chip` 11/16 w500，padding h8/v6（视觉高 = 16+12 = **28**），圆角 4，
      底 `accent_subtle`，字 `accent`，**maxWidth 60 + Ellipsis（超 4 字截断）**，
      `accessibilityText` 报**全名**；无分组时不占位；命中区由整行承担
```

> **修正记录（2026-11-22，实现评审后）**：本节此前把行内上下 padding 写成 `10`、把 host 截断写成"中间省略"，两处都改掉了——`10` 不在间距白名单内（改 8，`minHeight 64` 会吸收差额，视觉无变化）；中间省略需要手工裁字符串，成本不值，且端口已独立，尾部省略不影响四要素。

**排布裁决理由（leader 原话转述）**：把标签和名称放同一行，**名称会被分组名长度漂移挤压**——名称是用户自己起的检索键，被压就找不到自己的节点；地址是技术字段，截断可接受。移到元信息行后，容量不再取决于用户起了多长的分组名，**名称永远独占 222vp**。

- 溢出 `Menu` 项顺序：**编辑 / 上移 / 下移 / 分隔 / 删除**（删除项文字 `danger`）。
- 空列表：必须给空状态（24×24 图标 + `body` 14/22 `text_secondary`「还没有节点」+ `body-sm` 说明 + 主按钮「导入链接/订阅」），**不允许纯空白**。

### 4.5 `ChipGroup`（筛选 chips：分组 / 日志级别 / 选项按钮组）

现有"选中=蓝底白字，未选中=灰底黑字"继续沿用，但补尺寸与状态：

- 选中：`accent` 底 / `text_on_accent`；未选中：`bg_chip` 底 / `text_secondary`。

- 选项按钮组超过 4 个时（NodeEdit 的传输有 5 个）**必须允许换行或横滚**：5 个 44 高按钮在 328vp 内总宽约 44×5 + 32 = 252（按 min-width 44 计）尚可，但一旦字号放大或系统字体缩放就会溢出 ⇒ 用 `Flex({wrap: FlexWrap.Wrap})`。

## 7. 深色模式

### 7.1 落地方式（必须）

1. 新建 `entry/src/main/resources/dark/element/color.json`，**键集合与 `base/element/color.json` 完全一致**（否则缺键会在深色下回退到 base，出现浅色块）。
2. 页面源码中**不允许任何 hex 字面量**，全部 `$r('app.color.<token>')`。`ConnectionViewModel.colorHex: string` **必须改类型**：不能返回 hex 字符串，改成返回语义枚举 `ConnStatus { DISCONNECTED, CONNECTING, CONNECTED, ERROR }`，由页面映射到颜色资源。**这是深色模式的硬前提**——ViewModel 目前直接把 4 个 hex 塞进 UI，是唯一一处"颜色跨层传递"。
3. `start_window_background` 需在 `dark` 下给 `#0E1013`，否则启动瞬间白屏闪烁（"闪白"是最容易被用户当成 bug 的深色缺陷）。
4. 不强制 `setColorMode`，跟随系统（默认行为）；若后续要"手动选择"，再加设置项，本规格不引入。

### 7.3 哪些颜色**不能**简单反相（重点）

| 对象 | 为什么不能反相 | 正确做法 |
|---|---|---|
| 品牌/主色蓝 `#1565D8` | 反相后是橙色，语义完全变了；且 `#1565D8` 在深底上对比仅 2.1:1 | 换成**提亮版** `#6BA1FF`（同色相、提亮度），不是反相 |
| 语义色 绿/红/橙 | 直接反相会得到紫/青/蓝，全部丧失语义；高饱和原色在深底上还刺眼（眩光） | 保留色相不变，**降饱和 + 提亮度**（`#17703A → #4CCB77`） |
| 选中行淡绿 `#E8F5E9` | 反相成深绿后与 `success` 撞语义，用户会以为"节点已连接" | 选中一律改 `accent_subtle`（浅蓝），深色下 `#1B2740` |
| 阴影/elevation | 深底上阴影不可见，等于层级消失 | **全程不用阴影**：用 `bg_surface` vs `bg_surface_alt` 的亮度差 + 1vp `border_subtle` 表达层级 |
| 半透明遮罩 | 反相变白色蒙层，视觉上是"曝光过度" | 深色下加重不透明度（.45 → .65），保持黑色 |
| 系统图标颜色 | 从现在固定 `#546E7A` 继承，深底对比不足 | 图标色跟随 `text_tertiary` / `accent` 令牌，不写死 |
| 启动窗口底色 `#FFFFFF` | 反相逻辑不会覆盖 json 里的字面量，深色启动白闪 | 必须手写 `dark/element/color.json` 覆盖 |
| `#F5F5F5 / #FAFAFA / #F0F0F0` 三灰 | 深色下三者反相后几乎同色（`#0A0A0A`/`#050505`/`#0F0F0F`），层级丢失 | 归并为 `bg_canvas / bg_surface / bg_surface_alt` 三级，深色下分别给 `#0E1013 / #171A1F / #1E2228`（明度差 ≥ 5%） |

### 7.4 深色验收判据

- `dark/element/color.json` 存在，且**键集合与 base 完全相同**（用脚本比对 key 列表，不允许缺键/多键）。
- 8 个页面在深色下逐个截图：**无白底块、无浅色文字配浅底、无白闪**。
- 每个页面至少一个"深色专属"问题被修过：首页横幅、列表选中行、输入框边界、日志级别色 —— 这四处是浅色写死最容易漏的。

### 10.4 首页文案：定位语与状态句分离 ✅ 已裁决（2026-11-22，第二版：禁用 "SOCKS" 字样）

**结论**：`SOCKS` 是协议名，用户读不懂，也违反"不写实现细节"。文案拆成两条，**各归各位**：

| 位置 | 文案 | 规格 | 变量性 |
|---|---|---|---|
| **副标题位**（应用名下方） | **「本地转发，规则由你定」**（11 字，≤16 字） | `body-sm` 13/20 `text_secondary` | **固定**，不随状态变化 |
| **状态描述位**（状态行内，即 `hint`） | 见 10.4.1 三档回退 | `body-sm` 13/20 `text_secondary` | **随状态变化**，只出现在状态行 |

#### 10.4.1 状态句三档回退（顺序写死，不许各写各的）

| 档 | 条件 | 文案 |
|---|---|---|
| 1 | 有节点名（`name` 非空） | **「当前走 <节点名>」** |
| 2 | 无节点名，但有 `host:port` | **「当前走 <host:port>」** |
| 3 | 两者都没有 | **「当前已连接（未选节点）」** |

未连接态（DISCONNECTED / ERROR）不套用此表：DISCONNECTED 且**有**节点 → **「已就绪：<节点名>」**（2026-11-22 采纳实现：比"仅本机提供代理"更有用，用户点连接前就知道要用哪个节点）；DISCONNECTED 无节点 → 「当前仅在本机提供代理」；ERROR → 错误原因原文。

**禁止项**：连接过程**不放倒计时/秒数承诺**（如"最多等待 8 秒"）。8s 是 `KernelService.CONNECT_TIMEOUT_MS`，可调；写进文案就成了对用户的承诺，调优一变文案即失真，且会让用户把"超时"读成"坏了"。要缓解等待焦虑用 `LoadingProgress`，不用数字。

#### 10.4.2 `deriveView()` 签名约束（从接口上堵住实现词回流）

- 入参**只允许传展示字符串**（如 `nodeDisplay: string`），**禁止**传 `socks` / `port` / `mode` / 任何实现字段。
- 理由：一旦签名里出现实现字段，后续维护者必然在 `deriveView()` 内部拼出 "SOCKS :1080" 这种字符串，文案规范会从最底层被绕过。**签名是比约定更强的约束。**
- 三档回退的拼接在**页面侧**完成（页面知道 `name` 与 `host:port`），`deriveView(nodeDisplay)` 只负责选择模板句。

**连带的 3 处必改（否则验收过不去）**：

1. `ConnectionViewModel.deriveView()` 的 4 条 `hint` 现在都含 "SOCKS"/"内核" 字样（如"点击开关启动内核（当前仅本地 SOCKS，未接节点）"、"内核已启动（本地 SOCKS 监听中，尚未接入节点）"）→ 全部按 10.4.1 改。
2. 首页 `socksInfo` 那一行（`本地 SOCKS 127.0.0.1:<port>（已启用口令鉴权）`）→ 改 **「本机代理地址 127.0.0.1:<port>」**，归**诊断类信息**层级：`caption` 12/16 `text_tertiary`（**不得与节点名 `body-lg` / 状态 `display` 同权重**）。**信息保留**，只换词、去掉实现细节括号。
3. `DevPanel` 的说明文字可保留技术词（那是调试面），但**首页与 Settings 用户可见文案不含** SOCKS / freedom / 内核直连。

#### 10.4.3 诊断信息三条附加约束（leader 2026-11-22 拍板"保留信息、换词"）

> 理由（leader 原话）：端口每次连接轮换，是用户报障时唯一能自证的线索；删掉信息等于把排障成本转给下一个人。

| # | 约束 | 落点 |
|---|---|---|
| D-1 | 该行归**诊断类信息**层级（次要色 + 12fp），**不能与节点名/状态同权重** | §4.3 StatusHero：`caption` 12/16 `text_tertiary` |
| D-2 | **Logs 页也必须能读到当前代理端口**——首页那行不能是唯一暴露点，否则用户一断连就无从查 | §5.6：Logs 顶部加诊断行（见下） |
| D-3 | **长按复制** `127.0.0.1:<port>`，报障时用户能直接粘出来。**不改视觉，只加事件**（不加图标、不加下划线、不改颜色） | §4.3 / §5.1：`LongPressGesture`(500ms) → `pasteboard.setData` → 轻提示「已复制」 |

**Logs 页诊断行规格（D-2）**：

| 状态 | 文案 | 样式 |
|---|---|---|
| 已连接 | `当前代理地址 127.0.0.1:<port>`（长按复制） | `caption` 12/16 `text_tertiary`，紧贴脱敏说明下方 |
| 已断开、但本次启动内连接过 | `最近一次代理地址 127.0.0.1:<port>（已断开）`（长按复制） | 同上 |
| 本次启动从未连接 | `暂无代理地址记录（本次启动未连接过）` | 同上 |

- **为什么要第三种状态**：D-2 的理由是"用户一断连就无从查"。若断连后直接显示"暂无端口"，这条约束就等于没做。**"最近一次"必须能读到**，否则用户报障时手里没有可自证的地址。
- **实现前提（已批准 2026-11-22）**：`SocksGuard` 暴露一个**只读** `lastEndpoint()`（仅进程内存，**不持久化**；应用重启后为空，此时落到第三种文案）。纯读接口，不改轮换逻辑、不写盘。

**`lastEndpoint()` 三条硬约束（leader 批准时追加，防止"只读"变借口）**：

| # | 约束 | 判定方式 |
|---|---|---|
| L-1 | 返回**不可变快照**（`{host, port}` 或空）；调用方拿到的对象**不允许改回写进** `SocksGuard` | 返回副本/冻结对象；评审确认无 setter、无共享引用 |
| L-2 | ~~只在"绑定成功"那一刻更新~~ → **在「端口轮换即刻」写入快照（早于内核启动）**；断开**不置空**；进程死亡后自然为空 → 落第三态（**2026-11-22 改口**，见下） | 单测：连接 → 断开 → 仍可读到原值 |
| L-3 | **不持久化、不进日志缓冲、不参与轮换决策**；允许被反复读而不改变任何状态（**幂等**） | 单测：连续调用 3 次返回值相等，且 `SocksGuard` 内部状态不变 |

**L-2 的代价（写清，避免被当成 bug 修掉）**：快照在 `rotate()` 时写入，而 `rotate()` 早于 `kernel.start()` ⇒ **启动失败时快照里会留下一个"尝试过但未监听"的端口**。这是**特性**（失败才是报障主场景，用户需要知道试的是哪个端口），但文案上不得声称"当前可用"，所以 Logs 必须用 `KernelService.isRunning()` 区分「当前 / 最近一次」。

**host 单一来源（必须）**：`SocksGuard` 的快照 host 与 `KernelConfigBuilder` 的 `listen` **不得各写一处字面量**（否则改监听地址时，Logs 会显示一个错的地址）。做法：提一个常量（如 `SocksGuard.LOCAL_HOST`），两处共同引用。**不加参数**——加参数会引入"日志地址"和"绑定地址"两个可变量，比现在更糟。
**验收**：全仓 `grep "127.0.0.1"` 只剩常量定义 1 处（文档/注释除外）。
- 数据来源：`SocksGuard` 当前端点；页面 `onPageShow` 读一次即可（与首页同源）。
- 可选（建议，不需要可跳过）：连接成功时 `Logger.info` 打一行「本地代理端口 <port>」，让导出日志里也留痕——**这一行必须脱敏后仍保留端口**（端口不是凭据，漏掉它反而废掉 D-2 的意义）。

**验收（可判定）**：
- `grep -i 'socks\|freedom\|内核直连'` 在 `pages/Index.ets` 的用户可见字符串（`Text('…')`、`TextInput` placeholder、`hint` 赋值）**= 0**；`ConnectionViewModel` 的 `hint` 字符串同样 = 0（`DevPanel` 除外）。
- `deriveView` 签名参数里**不含** `socks / port / mode / credential` 任一字段名（`grep "deriveView("` 人工过一次）。
- 三档回退可逐个构造验证：有 name / 只有 host:port / 都无。
- 副标题位**只有**定位语；任何状态句出现在副标题层即不通过（副标题 `Text` 绑定源必须是常量）。
- 副标题 ≤16 字且单行不折行；`<节点名>` 不做截断（超长交给 `Ellipsis`）。
- 长按诊断行 → 剪贴板内容**等于** `127.0.0.1:<port>`（无多余空白与括号）；长按 500ms 内不得触发整行点击。
- 断连后进 Logs 页，仍能看到「最近一次代理地址 127.0.0.1:<port>（已断开）」（D-2 反例检查：连接态读到端口不能只靠首页）。

**宽度核算（两段式，别只记一个数）**

文字列固定 **222vp**（316 − 竖条 12 − 形态 34 − 溢出 48）：

| 场景 | 名称行 | 元信息行可用分配 | host 可用 |
|---|---|---|---|
| **无分组** | 222vp 独占 | 协议 ~47 + `:port` ~26 + 间隙 8 | **≈141vp ≈ 21 字符** |
| **有分组**（chip ≤60） | **222vp 独占（不受影响）** | 协议 47 + `:port` 26 + chip 60 + 间隙 12 | **≈77vp ≈ 11 字符** |

- 关键差异：**名称在两种场景下都是 222vp**，这正是 leader 裁决要换来的东西（原先 chip 在名称行时，名称被压到 ~156vp，且压多少取决于用户分组名多长）。
- 有 chip 时 host 只剩 ~11 字符（如 `hk01.ex…:443`）：**中间省略保留头尾**，端口永远完整可见；地址是可截断的技术字段，名称是不可截断的检索键——取舍明确。
- **协议短名映射**（展示层映射，不改数据）：`shadowsocks → ss`，其余 `vless / vmess / trojan` 原样。理由：`shadowsocks` 在 12fp 下要 73vp，白吃掉 host 的一半宽度。
- 若实测仍嫌 host 太窄，备选方案 B（需你点头）：chip 在窄空间下降级为**纯文字**「· 分组名」（去掉底色与 padding，省 16vp），host 随之回到 ~93vp；代价是分组从"标签"退回"普通文字"，四要素仍可见但分组不再视觉分组化。

**两个命中区是兄弟，不是嵌套**（leader 已确认按此执行）：
- 整行 `Row.onClick` 只负责 `pick(id)`（选择）；
- 溢出 `Button` **自己消费事件**（`Button` 自带手势会拦住父级 `onClick`）；
- **禁止**在整行外再包一层 click 容器 / `gesture` 包裹层——那会重新变成"整行点击 + 子点击"的双层结构，两个命中区互相吃事件；
- **禁止**给整行加 `hitTestBehavior(HitTestMode.Block)` 之类的兜底，行为要由"谁在上面"决定，不是由拦截决定；
- 菜单打开时（`bindMenu` 自带遮罩），点同行落在遮罩上 → 只关菜单，**不得改变 `selectedId`**（自检 A-15）。

## 12. 明确不做（边界）

- **不引入任何图片/位图资源**，不用第三方 UI 库。图标只用 `SymbolGlyph($r('sys.symbol.*'))`；`sys.symbol` 具体名称随 SDK 版本变化，**若某个名称不存在，退化为字形字符**（`← ⋯ ⚠ ✓`），不得为此新增 media 资源。
- **不加底部 Tab 栏**。当前是"首页 + 二级页"导航，加 Tab 会与"返回"顶栏重复，且减少列表垂直空间。现状导航结构保留，只重做样式。
- **不改动任何业务逻辑、状态机、持久化**。`Nodes` 的 `cfgRev` 重渲染机制、`NodeEdit` 的 `$$` 双绑写法、`Index` 的 `bestEffortStop` 收尾逻辑一律不动——那些是踩过坑的结论（源码注释已写明），视觉改造不得引入回归。
- **不改动 `DevPanel` 的探针与脱敏逻辑**（`maskSensitive` 是安全边界，不是视觉对象）。
- **不加动画**。除按钮按下态外不引入转场/淡入；连接状态变化只改文字与颜色，避免"连接失败时界面跳动"放大焦虑。
