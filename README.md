# xray-harmony

基于 Xray-core 的 HarmonyOS（NEXT）代理客户端 —— **需求、方案与 PoC 执行包**。

> 当前仓库只有**文档**，没有实现代码。产品能否成立取决于一组尚未执行的 PoC 实验。

## 文档入口

**→ [`doc/README.md`](doc/README.md)**（文档集唯一入口，含三件必知事项与按角色的阅读顺序）

## 三件最需要先知道的事

1. **关键路径依分发形态而定**：自用/内测无资质审批前置，工期由 PoC 决定（约 5~6.5 周）；**公开发行**才需 IP-VPN 类《增值电信业务经营许可证》（法定 60 日内，企业主体 + 注册资本门槛），属月级且类目可上架性存疑。
2. **产品可行性押在 `J-01` 一个技术假设上**：Xray 内核以 so 同进程加载 + 经 tun2socks 跑通 tun 数据面 + v6 最小用例。**不通过 = 产品在当前平台不成立，不是"降级交付"**。
3. **默认 fail-closed，但没有进程级 kill switch**：用户划掉应用卡片 → 系统撤销 VPN → 流量恢复直连（平台行为，已如实披露）。

## 关于第三方代码

本仓库**不包含**任何第三方源码。调研阶段使用的参考实现均未入库（见 `.gitignore`）：

- **Hey**、**v2rayNG** 为 **GPL-3.0**（传染性），入库会污染本仓库许可；
- **Xray-core** 为 **MPL-2.0**（文件级 copyleft），本项目采取「零修改 + 动态链接分发」以最小化义务；
- **libXray** 为 **MIT**。
